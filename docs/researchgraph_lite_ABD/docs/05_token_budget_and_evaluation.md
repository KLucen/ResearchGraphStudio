# 05 Token预算、真实统计与阅读效果评估

## 1. 统一预算口径

统计 **输入Token + 输出Token**，包含所有失败重试、格式修复、关键词转换；对已命中的缓存只统计0个新生成Token。Provider提供usage时以该值为准，只有Provider不返回usage时才估算并明确标记。不同厂商的“推理Token”如已包含在其总输出计费Token中，**不可重复计入**。

## 2. 旧基线（由Codex估算，尚非实测）

- 知识图谱构建：30万–80万Token/篇。
- 图谱+3–5次问答+语义Lint+Wiki：100万–250万Token/篇。
- 单次老问答上下文可能接近16万Token。

不能据此直接断言Lite一定降低多少比例，需在真实模型环境对样本论文建立计量基线。

## 3. Lite目标预算（有明确用户行为的场景）

| 操作 | 数量 | 单次目标 | 小计 |
|---|---:|---:|---:|
| 本地解析/索引 | 1篇 | 0 | 0 |
| B卡片 | 1 | 6k–12k | 6k–12k |
| A小节标准导读 | 3 | 3k–6k | 9k–18k |
| D局部QA | 3 | 2k–5k | 6k–15k |
| 合计 | 7次显式AI动作 | — | **21k–45k Token** |

本目标成立的条件：中等长度科研论文，三节中等长度Section，问答检索范围受限、没有大量重试、Model返回稳定结构化输出。**不是整篇每节精读的预算**；用户大量问答或要求深度解释会增长。

对应相对降低（仅作为设计目标）：以30万–80万Token旧建图为参照，21k–45k大约少 **85%–97%**。比较的是**不同任务范围**，不代表同等科研信息覆盖率。

## 4. 强制成本保护

- 用户尚未点击任务：0模型调用。
- 后端生成前预估预算，超限时建议缩小范围而不是自动分片重跑；如要继续需明确同意。
- 用户在任务中只改变UI标签/图谱拖动，不触发模型调用。
- 同样输入和模型配置命中缓存；同一正在执行请求要合并。
- 卡片最多3条贡献/结果/局限，导读最多4重点/3问题/3术语，问答尽量直接回答、不写无关延伸。
- 对每种任务设置max_output_tokens和上下文上限，使用Provider支持的结构化模式；超过预算先裁减来源，不偷换引文。
- 429/网络故障有限退避；无法精确判断超时是否在服务端已计费时，记录该不确定性并提示用户。

## 5. 必须实现的观测字段

```text
task_run_id, paper_id, document_version_id, kind(B/A/D),
prompt_version, model_id, config_fingerprint, scope(section/span/paper),
input_span_count, estimated_input_tokens, actual_input_tokens?,
actual_output_tokens?, usage_source(provider/estimated/unknown),
retry_attempts, cache_hit, latency_ms, status, reason_code,
created_at, source_hash, response_hash, cost_estimate?
```

不要保存密钥；原文片段不默认写入远程可观测平台。缓存键不应包含API Key明文。记录失败重试Token与成功Token分开，防止出现“界面显示5万，供应商已经计费20万”的错觉。

## 6. 真实性验证清单

选择3种英文研究论文：结构清晰的实证论文、公式/表格较多的方法论文、综述/理论论文。每篇执行：

1. 只选论文、解析索引，验证0次模型调用。
2. B生成一次，二次打开命中缓存0新增Token；对六字段逐一核验原文。
3. 选择3节做A，比较导读是否包含“讲什么/重点/阅读问题”且不提前总结全文。
4. 3次D提问：术语解释、方法原因、证据不足问题，验证引用和拒绝猜测。
5. 调整PDF版本/模型/Prompt，验证缓存标为stale或键失效；不自动重算。
6. 模拟429、超时、不合法JSON、无匹配证据，检查费用、失败隔离与重试。
7. 报告实际Token/耗时/准确性与用户阅读任务完成度，观察是否命中目标区间。

评价指标：引用有效率、字段错误率、导读有用性（小样本用户评分）、QA证据支持率、每题Token、缓存命中率、故障后的重复调用率。不要用“平均Token少”代替阅读质量验证。
