# ResearchGraph Studio 界面优化开发方案

2026-11-22（Asia/Shanghai） · 界面已实施并打包

以引文修复版为基线。先让已保存的研究内容进入首屏，再统一控件、反馈和主题。范围包括论文工作区、知识地图、联系汇报、任务记录、归档管理和外观设置。

实现决策见 [ADR0071](adr/0071-workspace-appearance-and-quick-actions.md)。[进度](progress.md)记录最终测试、Windows 安装包和仍待实测的系统界面。

## 参考与取舍

Designeer 首页把搜索、分类和内容入口放在相邻区域，分类旁标注数量。卡片原地提供悬停预览，顶栏可切换系统、浅色与深色。这里借用它的分类与结果组织方式、悬停的就地反馈和可找到的主题设置。论文工作区以正文、引文和任务状态为首要内容，使用稳定的行高、低饱和背景和短过渡。展示性动效和大幅标题留给参考网站的场景。[Designeer 中文首页](https://designeer.org/zh)

## 页面排版

| 页面 | 调整前 | 调整后 | 验收重点 |
| --- | --- | --- | --- |
| 论文工作区 | 当前阅读来源在「论文解析操作」图标菜单内，查看来源与重新解析同列 | 论文标题下排三张阅读页签，旁边直接显示「查看来源 · 本地解析／模型解析」。双来源可切换，单来源显示可用来源。「更多操作」收纳重新解析和已有生成入口。窄窗让来源换行，论文回答入口附近注明本地索引要求。 | 切换来源延续现有本机记忆。切换、开菜单和浏览内容产生零模型请求。阅读页任务提示延续仅显示进行中任务名。 |
| 论文概览和精读 | 已有卡片结果时，模型授权和重新生成仍占据正文上方。分类按全量计算，结果受当前筛选影响 | 已有结果时先显示文章总览、卡片介绍、分类和卡片。分类与搜索、已读、收藏、已隐藏等查看状态放在一起。类别计数先应用共同筛选，再按类别汇总。重新生成、版面整理和公式识别放入对应次级操作。首次生成及失败时仍就地呈现可执行动作。精读保留章节目录、原文与批注的配对结构，放大后按阅读顺序换行。 | 同一筛选下分类数量与点击后的列表一致。首次生成和失败均可发现，已有部分结果仍可阅读。引文原文及定位可达。 |
| 知识地图 | 展开范围、语言与全屏在上方，类型开关混在画布下方图例中 | 上方分为「展开范围」「显示类型」「视图」三组。五种类型开关可换行，选中、未选用复选状态和颜色共同表达。底部图例解释节点类型、实线和虚线。宽窗保持画布与详情并排，窄窗详情顺序落在画布下方。 | 默认展开每页论文。切换节点类型、主题或全屏时，固定点与镜头保留。切换论文范围沿用现有定位策略。语言与现有右键入口保持可用。 |
| 联系分析与汇报 | 普通分析和重新分析的差异需要从文案推断。覆盖数字和操作先于报告要点，证据与两侧陈述分段 | 在授权框旁显示本次生效的范围和候选上限，如「同项目 · 最多 8 篇候选」。区分地图浏览筛选、可复用结果的普通分析和另存汇报的重新分析。汇报按「范围及实际比较数 → 摘要 → 对应点与适用条件 → 双方陈述及各自依据」排列。宽屏沿用双栏，把原文与定位放入对应论文一栏，窄屏按同序堆叠。依据链接标明关系，点击定位。 | 旧短报告和新详细报告均可读。命中缓存时显示实际复用结果。已有快照的覆盖数据如实显示。从汇报定位关系后，返回时能恢复原项目、专题、搜索及分页。已读仅由现有明确打开操作更新。 |
| 任务记录 | 任务状态、批次诊断、安全原因和动作在同一层级连续显示 | 紧凑行先显示任务名、状态、项目及时间。失败行突出原因和现有下一步，HTTP、批次、耗时和错误码放入「诊断详情」。本机恢复可用时显示实际保留数量与「0 次模型请求」。模型重试的发送和费用提示紧邻操作。 | 已恢复任务同时保留原失败状态和部分知识提示。发送状态与费用状态准确。阅读工作区仍无批次日志。 |
| 归档管理 | 行只显示标题、类型和时间，恢复与彻底清除同权重，确认使用系统样式 | 每行显示标题、类型、所属项目和时间，复用已有项目映射。恢复保持可见，彻底清除从「更多操作」或右键进入应用内确认。确认同屏显示对象、归属、清除影响及取消，初始焦点在取消。正在清理的行展示「继续清除」。 | 同名论文一眼可区分。缺少项目映射时如实显示归属不可用。Esc 或取消产生零清除请求，确认仅执行一次，清理未完成时恢复入口按原规则禁用。 |

主要改动入口为 [论文页](../apps/desktop/src/Papers.tsx)、[解析操作](../apps/desktop/src/PaperParsing.tsx)、[概览](../apps/desktop/src/PaperOverview.tsx)、[卡片集](../apps/desktop/src/PaperCardSet.tsx)、[精读](../apps/desktop/src/PaperCloseReading.tsx)、[知识库](../apps/desktop/src/ResearchKnowledgeBase.tsx)、[图谱](../apps/desktop/src/ForceGraph.tsx)、[任务记录](../apps/desktop/src/JobHistory.tsx)和[归档](../apps/desktop/src/ArchiveWorkspace.tsx)。

### 关键布局示意

```text
论文标题
论文概览   论文精读   论文回答       查看来源 · 模型解析 ▾   更多 ⋯
───────────────────────────────────────────────────────────────
文章总览
分类 [方法 4] [贡献 3] …                 搜索卡片    查看范围 ▾
卡片目录或结果列表                       所选卡片和原文依据

联系汇报标题
同项目 · 实际比较 3 篇 · 入选 5 篇
摘要
关系 01 · 对应点 / 关键差异 / 适用条件
本篇陈述与原文依据                       对照论文陈述与原文依据
```

示意中的数字为匿名设计样例。保持现有字体栈，首轮建议正文 15–16 px、行高 1.65–1.8，界面控件 13–14 px。长标题在列表中可截断，正文标题与可访问名称保留全名。用 8、12、16、24 px 的间距组织同组控件和内容区。在窄窗优先换行，正文、图谱和表格使用各自已有的滚动区域。

## 悬停、键盘与选择状态

| 调整前 | 调整后 | 理由 |
| --- | --- | --- |
| 列表、卡片、任务和归档各自定义反馈 | 可操作行使用轻底色或边框反馈，选中增加持续的边框或指示，键盘焦点留独立轮廓。截断的标题需要时显示已加载全名。 | 鼠标经过、键盘停留和已选状态有清楚的区分，列表高度稳定。 |
| 图谱已有节点邻域悬停，键盘及关系两端的反馈可加强 | 复用节点邻域高亮，悬停或键盘聚焦一条边时强调两端和连线。邻域外信息轻度减弱，退出恢复原选中。拖动、平移时抑制临时预览，点击才切换详情。 | 快速看清两篇论文的连接点，画布布局和已选内容稳定。 |
| 精读和汇报已能点击定位原文 | 悬停或键盘聚焦批注编号、依据链接时，轻度高亮同一条已加载引文及对应说明。点击沿用既有定位，全文或含操作的详情通过点击打开。 | 读者在正文与分析之间核对时能看清对应，旁侧预览不会移动阅读位置。 |

高频悬停建议只为颜色、边框或透明度做约 100–140 ms 过渡。键盘焦点即时显示。鼠标专属样式适用于支持 hover 的精细指针。系统开启减少动态效果时，反馈仍在，过渡关闭。自定义提示支持 Esc 关闭、移入提示继续阅读以及焦点离开恢复。付费授权、恢复和清除保留可见入口。悬停、聚焦与主题切换仅更新显示，产生零模型请求、零图谱布局写入、零已读或归档变更。[W3C 悬停或聚焦内容](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) · [W3C 可见焦点](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

## 明暗模式

- 在「设置与诊断 → 外观」增加「跟随系统 / 浅色 / 深色」。推荐无记录时跟随系统，手动指定后跨启动记忆。仅跟随系统档监听 Windows 主题变化。偏好放本机 WebView 存储，存储或值不可用时回到系统档。
- 用现有浅色建立基线，从 [全局样式](../apps/desktop/src/style.css) 抽取背景、内容面、浮层、正文、次级字、边框、交互状态、语义状态和焦点等 CSS 变量。先迁移底层控件，再迁移页面。图谱与引文各有语义颜色表，浅深两套使用同一分类名称、图例和位置标记。
- 深色建议用暖石墨背景和分层内容面，保留柔和绿作为操作色。普通文字、次级字、链接、选中态、危险操作、图例与关键连线分别验对比。普通文本以 4.5:1 为目标下限，关键非文本部件与必要状态以 3:1 为目标下限。图谱类型和精读标记同时保留名称、线型、编号或轮廓。 [W3C 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [W3C 非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 首次渲染前以同源脚本及基础样式解析主题，设置根节点主题和 `color-scheme`，重用原生输入控件外观。应用的脚本策略沿用当前 CSP。React Flow 控件、SVG 连线、弹层、全屏画布、公式及原图容器均纳入检查。PDF 原图按原色显示。Windows 标题栏、冷启动背景和原生对话框单独验收，出现问题时再评估宿主接口及必要的最小权限。 [桌面入口](../apps/desktop/index.html) · [Tauri 配置](../apps/desktop/src-tauri/tauri.conf.json) · [图谱颜色](../apps/desktop/src/graphAppearance.tsx) · [精读标记](../apps/desktop/src/readingHighlights.css)

| 配色角色 | 浅色候选 | 深色候选 |
| --- | --- | --- |
| 应用底色 / 内容面 | `#F7F7F3` / `#FFFFFF` | `#171D1A` / `#212925` |
| 正文 / 次级字 | `#243E38` / `#54645C` | `#E6EFE9` / `#AABBB1` |
| 操作色 / 选中底色 | `#1D5040` / `#EDF4EF` | `#93DCB4` / `#2A3831` |

按色值组合计算，现有次级字在浅色画布上约 3.84:1，候选浅色次级字约 5.83:1，候选深色次级字在内容面上约 7.42:1。实现时以实际页面中的背景、文字大小和组件状态逐项核验。

## 开发顺序

| 阶段 | 工作和依赖 | 可验收交付 |
| --- | --- | --- |
| 1 · 固定基线和共用样式 | 记录匿名阅读、失败任务、密集图谱、双侧汇报和同名档案在浅色下的截图与行为。抽取语义颜色、焦点和交互状态，先验证浅色色值和布局。 | 可重复的夹具、行为测试和视觉对照基线。 |
| 2 · 阅读与任务 | 优先调整来源入口和已有结果的首屏，统一卡片计数，分层呈现任务动作与诊断。使用阶段 1 的样式。 | 双来源切换、首生成、失败恢复、合法重新生成及费用文案可独立回归。 |
| 3 · 地图、汇报与归档 | 把显示类型移到画布上方，接入现有图谱反馈和双侧证据排版。归档复用现有项目归属和确认接口。阶段 2、3 可按页面并行，公共样式变更先合并。 | 地图和汇报往返、旧结果复用、显式重跑、无联系或部分覆盖，以及同名项目归档可独立回归。 |
| 4 · 接通外观选择 | 完成剩余页面、弹窗、右键、表单、公式和图谱的两套颜色。走通初始化及偏好测试后开放设置。 | 三档可切换、重启可恢复、系统变化可跟随，冷启动无明显白闪。 |
| 5 · 综合验收和交付 | 全量回归后制作隔离 Windows 安装包，验证 WebView2 和原生交互。按阶段保留可独立回退的样式与界面改动。 | 安装包、测试结果和原生操作记录，浏览器、隔离包内和日常覆盖结果分开记录。 |

此方案默认沿用现有 React、CSS、Lucide 和 React Flow。布局、交互和主题在前端落地，复用现有引文、归档、用量和授权接口。后端来源校验、恢复预览指纹、任务计量和数据库迁移链沿用引文修复版。

按一名开发者、复用现有接口估算约 7–10 个开发日，包含回归和隔离打包。

## 回归矩阵

| 验证场景 | 推荐入口和断言 |
| --- | --- |
| 阅读与卡片 | 扩展 `workspace.spec.ts`、`card-set.spec.ts`、`paper-reading.spec.ts`。覆盖本地、模型、双来源，已生成、无结果、校验失败、已有部分知识和长标题。检查筛选数量和原文定位。 |
| 地图与汇报 | 扩展 `knowledge-map-context.spec.ts`、`knowledge-map-labels.spec.ts`、`knowledge-fullscreen.spec.ts`、`knowledge-detailed-report.spec.ts`。比较过滤、主题切换及全屏前后的选中、坐标、固定点与镜头。双侧引文在两种布局均能打开。 |
| 任务与归档 | 扩展 `JobHistory.test.tsx`、`archive-workspace.spec.ts` 和 `context-menu.spec.ts`。覆盖待处理、失败、部分恢复、同名不同项目以及清理待重试。测试键盘焦点、Esc、取消和只确认一次。 |
| 外观与响应式 | Edge 覆盖三档偏好与两种系统配色、模拟重启、动态切换、减少动画和强制颜色。采用 1440×1000、1280×850、950×680 及浏览器窄窗，Windows 单独复测最小窗口、125% 缩放、原生全屏与原生对话框。 |
| 行为和证据 | 以现有引文合同、恢复测试、收费授权和请求计数为基线，验证主题和悬停零副作用。确认时沿用相同恢复指纹、精确来源验证和旧响应留存。全量构建使用隔离数据及合成响应。 |

实施时运行 `pnpm check`、`pnpm format:check`、`pnpm test` 和 `pnpm --dir apps/desktop test:browser`。Windows 交付沿用 [构建脚本](../scripts/build-windows.ps1) 和 [隔离验收脚本](../scripts/verify-windows-install.ps1)，补测真实 WebView2 的主题切换和原生弹层。

发布顺序按「先能更快读，再能更轻松核对，最后统一深浅外观」推进。首个可独立验收的交付包含论文首屏和失败任务动作。主题底座从第一阶段纳入，外观设置随整套界面覆盖一起交付。
