# 01. 轻量知识图谱产品设计

## 定位
轻量知识图谱是 ResearchGraph Lite 论文概览中的可视化组成部分，不是独立的完整科研知识图谱系统。

论文概览包含 PaperCard（研究问题、动机、方法、贡献、发现、局限）和 LightGraph（单篇论文内部少量核心概念及关系）。A（章节导读）和 D（按需问答）沿用原 Lite 规范。LightGraph 只扩展 B。

## 用户流程
1. 用户在 Zotero 中选择论文。
2. 软件本地解析 PDF、目录和章节文本，不调用 LLM。
3. 用户点击“生成论文概览”。
4. 一次模型请求返回 PaperCard + LightGraph。
5. 后端校验、保存并投影图谱。
6. 用户在论文概览页浏览卡片和图谱，拖动/点击节点查看详情。
7. 用户后续进入 A 或 D 时，复用本地章节索引，不需要先生成完整知识图谱。

## 图谱包含
- 单篇论文内部的研究问题、概念、方法、贡献和发现。
- 节点中英名称：中文标签优先，保留论文中的英文术语。
- 简短中文节点说明。
- 少量语义明确的有向关系。
- 节点/关系表达性质：论文明确表达或 AI 归纳。

## 图谱不包含
- Evidence / Citation / Quote / Page / SourceSpan 节点或字段。
- 逐条证据审查、段落定位和引文对齐。
- Experiment、Condition、Metric 等细粒度对象的独立节点。
- 跨论文实体融合、跨论文支持/反驳、条件化比较。
- Lint、Wiki 自动演化或完整 Knowledge Evolution。
- 由模型生成图谱坐标或布局。

## 节点类型
| 类型 | 含义 | 示例 |
|---|---|---|
| RESEARCH_QUESTION | 论文试图回答的问题 | 模型如何理解他人意图 |
| CONCEPT | 核心理论或概念 | 心智理论 |
| METHOD | 核心方法或技术 | 参数模式分析 |
| CONTRIBUTION | 作者声称的主要贡献 | 内部机制分析框架 |
| FINDING | 论文报告的主要发现 | 特定参数模式与推理表现相关 |

建议每篇 6–12 个节点，最多 12 个。内容不足时允许更少，不得补齐数量。

## 关系类型
| 类型 | 方向与语义 |
|---|---|
| INVESTIGATES | RESEARCH_QUESTION → CONCEPT |
| USES | RESEARCH_QUESTION → METHOD |
| ANALYZES | METHOD → CONCEPT |
| YIELDS | METHOD → FINDING |
| CONTRIBUTES_TO | FINDING → CONTRIBUTION |
| RELATED_TO | 其他有明确语义关联的节点，仅在没有更具体关系时使用 |

## UI
位置：论文概览页面内的“知识关系图”区域。
- 力导向布局或项目现有图谱布局。
- 拖动节点；缩放和平移画布；适配全部节点。
- 点击节点打开右侧详情面板。
- 节点详情：中文标签、英文原词、节点类型、中文说明、basis。
- 点击边显示关系中文释义和 basis。
- 按节点类型过滤；选中节点时高亮一跳邻居。
- 重置布局；用户拖动后保存位置；重新打开论文时恢复。
- 图谱为空或节点过少时显示空状态，不报错。

节点主标签使用 label_zh，英文副标签使用 label_en。`EXPLICIT` 显示“论文明确提及”；`INFERRED` 显示“AI归纳关系”。

## 语义边界
LightGraph 是阅读导航和概念组织工具，不是经过证据核验的科学论证网络。
- EXPLICIT 表示输入论文文本明确表达了该节点或关系，不代表研究结论已独立验证。
- INFERRED 表示模型根据论文内容归纳出的组织关系。
- UI 应标注“AI生成的单篇论文概念图；非独立证据验证”。
