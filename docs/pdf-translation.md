# 文献翻译

更新：2026-11-11（Asia/Shanghai）。文献翻译是按需的版式翻译功能，使用软件中已经保存的模型 API。默认安装包自带 PDFMathTranslate-next **2.10.2**、BabelDOC **0.7.1**、独立 Python 运行时和字体、版式模型等离线资源，无需另装 Zotero 插件、Server 或填写 Python 路径。具体交付包及安装验证结果以 [开发进度](progress.md) 为准。

## 使用流程

1. 在“设置与诊断 → 模型”保存提供商连接和模型。已有可用配置可以直接复用，无需为翻译重复填写 API Key。
2. 从左侧项目树选择已本地解析的论文。在上方论文阅读工作区切换到“文献翻译”；论文信息位于工作区后方，默认折叠，可随时展开。
3. 选择模型和输出格式：**双语 PDF**或**中文 PDF**。新界面默认双语；旧调用及历史仍兼容两种同时生成。当前翻译范围为全文。
4. 设定最多模型请求数及累计输入估算限额，执行预检。预检核对本地运行资源、源文件、模型、选项和缓存，不启动排版、不调用模型。文件、模型、输出格式、运行方式或预算改变后需要重新预检。
5. 确认将论文文本发给所选模型后，明确提交翻译。软件在本机处理 PDF 和版式，模型 API 接收文本与提示，不上传整份 PDF 文件给模型接口。
6. 引擎完成、所选 PDF 验证通过且自建进程树回收后，任务发布完成。打开对应中文或双语 PDF，由系统阅读器查看；可在阅读器中另存。

“引擎已生成”只表示生成并通过文件校验，不代表全文翻译或科学表述已经人工验证。导入、切换论文、预检、查看历史、打开译文和缓存命中都不会自动发起模型调用。

## 缓存、用量与取消

缓存绑定 PDF 修订/哈希、模型及相关参数、运行协议和输出格式。新建随包任务还冻结 `translation_request_policy=text-chat-minimal-1` 并纳入缓存身份，避免与旧参数转发策略的结果混用。更改 `mono/dual/both` 需要对应缓存；历史未记录格式的任务按 `both` 保持兼容。旧版结果仍属于原论文修订，不能作为当前修订的新结果。已有任务未记录请求策略时，其原快照、参数转发和缓存键保持，不回写新策略。

每个实际模型请求写入统一 Model Usage，任务类型为 `pdf_translation`，可在“设置与诊断 → Lite 用量”查看。一次翻译通常有多次请求，不把一个任务算成一次调用。供应商实际返回 usage 才填实际 Token，缺失保持未知；费用没有价格依据时也为未知。

最多请求数和累计输入保守估算由本机代理执行。UTF-8 字节估算不是供应商实测 Token 或金额硬上限。单次输出最多 8192 Token，已知模型上限更低时采用更低值；截断或上游失败停止后续请求，不自动再次收费重发。任务内完全相同的成功请求可以复用。

API Key 保留在操作系统凭据存储中，翻译引擎只收到临时本机地址和一次性票据。取消或应用退出撤销票据，阻断新请求并尽力关闭在途连接；供应商已收到的请求仍可能计费。默认随包模式和托管外部模式仅关闭本应用启动的进程树，正常成功在回收后发布。重启不会自动续发中断翻译。

## 模型兼容与失败提示

新建随包翻译任务复用所选模型的连接、模型 ID、凭据引用、超时及已知输出能力，使用独立的 `text-chat-minimal-1` 请求策略。上游请求只发送文本 `model/messages` 和受控输出上限，不重新加入阅读配置中的 `temperature`、`top_p`、`reasoning_effort` 或模型适配器附加字段；阅读模型配置本身保持不变。翻译不要求 JSON 输出、流式响应或工具调用。

临时代理可以接收并校验翻译 SDK 的有限兼容字段，例如 `stream=false`、有效采样参数和输出上限，再依据冻结策略重建上游请求。这些输入不能改变冻结模型或绕过上限；流式、结构化输出、工具、图像及非空 `extra_body` 仍被拒绝。用量审计只保存实际上游请求的字段名、请求哈希和输入字节估算，不记录论文正文、请求头、票据、真实 Key 或供应商错误正文。

旧版提示“模型代理预算或请求校验失败，后续请求已阻断”把多个失败原因合并展示。用户本次反馈的历史错误码为 `TRANSLATION_PROVIDER_FAILED`，只能确认模型请求链路失败；现存记录不足以确定是参数、鉴权、网络还是响应问题，不能据此断言已发生 HTTP 400。新版按实际可观测结果分类：

| 错误码                                  | 含义与处理                                                                                |
| --------------------------------------- | ----------------------------------------------------------------------------------------- |
| `TRANSLATION_BUDGET_EXCEEDED`           | 请求数或累计输入估算达到本次上限；核对用量后重新预检并明确提交。                          |
| `TRANSLATION_TEXT_ONLY`                 | 翻译引擎请求不符合受控文本协议；检查运行时版本与模型配置。                                |
| `TRANSLATION_PROVIDER_REQUEST_REJECTED` | 模型接口返回其他 HTTP 4xx；检查 Base URL、模型 ID 及接口参数兼容性。                      |
| `TRANSLATION_PROVIDER_AUTH_FAILED`      | HTTP 401/403；检查 API Key 与端点。                                                       |
| `TRANSLATION_PROVIDER_RATE_LIMITED`     | HTTP 429；稍后再明确提交，不自动重试。                                                    |
| `TRANSLATION_PROVIDER_TRUNCATED`        | `finish_reason=length`；结果被截断，不发布译文。                                          |
| `TRANSLATION_PROVIDER_RESPONSE_INVALID` | JSON、choices、文本或结束状态不兼容；缺失、null 或未知 `finish_reason` 不推定为正常结束。 |
| `TRANSLATION_PROVIDER_FAILED`           | 其他请求失败，例如网络、服务端错误或凭据回显保护；保留一般失败，不补造具体 HTTP 原因。    |

上述失败会撤销任务票据并阻断后续模型请求，不自动降级或再次收费重发。失败记录及已返回的实际 usage 保留；缺失 usage 继续为未知。错误分类用于定位接口问题，不代表真实文献翻译质量已通过验收。

## 数据与文件

- 原始 Zotero 附件和直接导入 PDF 不被译文覆盖。新任务先核对原始字节与论文修订哈希。
- 随包运行环境的配置、缓存及工作文件在应用控制的本机目录中隔离，必要排版资源随安装提供，用户不需自行安装依赖。
- 译文在应用数据目录独立保存，打开前核对受管路径、哈希、大小和 PDF 格式，不接受任意返回路径。
- 翻译是阅读辅助，不替换 Section/Span 原文，不成为证据问答引用或 LightGraph 作者证据，不自动回写 Zotero。
- `lite0008` 升级前自动备份，在已有 Lite 库上增量增加输出格式并调整未来翻译默认设置，不清空旧论文、成果、布局、历史译文或任务。

## 高级：外部翻译服务

正常使用选择“软件自带引擎”即可。高级区域保留此前外部服务设置：

- **按需自动启停**：独立安装专用 zotero-pdf2zh Server 4.1.8 和完整 pdf2zh_next 环境后，提供 Python、`server.py` 与空闲 loopback 地址。应用仅在明确非缓存任务中启动它，不接管已有端口。
- **手动连接**：自行运行专用 Server，软件只连接，不负责关闭。该外部协议没有翻译子进程取消 API，撤销代理后排版可能仍继续。

旧路径不会因升级删除，已有任务的运行时快照保持；无快照的旧历史按 `manual` 解释。默认新任务配置使用 `bundled`，不会把历史任务重新绑定到随包引擎。外部安装仍由其维护者管理，其通知检查、首次资源下载和工作文件行为不适用随包资源说明。

## 构建与验证

开发构建使用 `scripts/prepare-translation-runtime.ps1`，从固定 manifest 下载并校验官方发行包及来源材料，输出到被 Git 忽略的安装资源目录；已有匹配资源可重复验证。原始许可证、固定版本源码和构建说明随运行时 `source/` 分发，详见仓库 `scripts/translation-runtime-notices.md`。这不把第三方大文件纳入 Git，也不作许可证法律结论。

本轮真实模型调用 **0**。实际引擎合成 Provider 联调、隔离安装与桌面验证必须按 [进度](progress.md) 的实测结果分别判定，本页不提前记为通过。复杂版面、公式、中文字体与扫描 PDF 的真实翻译质量仍需单独验收。

架构依据见 [ADR0038](adr/0038-bundled-translation-and-reading-layout.md)，请求策略与错误分类见 [ADR0039](adr/0039-translation-proxy-request-policy.md)。[ADR0036](adr/0036-optional-pdf-translation-bridge.md) 和 [ADR0037](adr/0037-managed-translation-server.md) 为外部桥接演进记录。默认运行时来自官方 `PDFMathTranslate-next/PDFMathTranslate-next`；外部兼容协议来自 `guaguastandup/zotero-pdf2zh`，后者不是默认安装前置。
