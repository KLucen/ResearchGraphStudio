# ADR 0003：工具所有权与受控知识演化

日期：2026-10-27（Asia/Shanghai）。状态：已采用为计划基线，待实现验证。

依据：[四份补充材料 S1–S4](../design/source-register.md)与用户本轮更新计划要求。保留 ADR 0002 的 Tauri/Conda/SQLite 技术路线；补充其中工具协作和导出范围，更新旧四阶段计划。新范围以[计划 v0.4](../development-plan-v0.4.md)为准。

## 决定

1. 保持 v0.1 的 5 篇论文证据/条件/关系/审核闭环。Zotero 适配、自动增量演化与批量实验仍在 v1.0；新材料的“默认 Zotero”是完整产品入口，不能据此扩大当前首版。
2. v1.0 以 Zotero 为原文和题录中心，只读 Local API。ResearchGraph 维护索引、证据、知识版本和审核；Obsidian 维护个人笔记并浏览授权目录中的生成 Wiki。直接 PDF 是独立来源，允许仅引用或用户选择托管副本，不默认复制 Zotero PDF。
3. 将 v1.0 从“增量图谱 + 导出”扩展为受控 Ingest/Query/Lint：Wiki 与结构化知识建立依赖，新增证据产生可审核提案，Query 沉淀需审核，语义 Lint 不能自动修正科学结论。更新的是知识资产，不是模型权重。
4. 个人观点保存为 UserInsight/Hypothesis，带作者、来源文件版本和证据状态。原文证据、论文归属主张、模型推断、个人假设分开处理；授权读取笔记不等于授权写回。
5. 所有 accepted 科研主张/关系的语义变更保留新旧版本、审核人与依据。概念合并同样需审核，保留旧 ID 和可逆映射。RELATED_TO 仅作概念关联，不扩展五类主张关系。
6. 知识对象保持六态。附件的 machine_checked 映射 verified，pending_review 是队列；Job、EvolutionProposal、WikiOutbox 各自有生命周期，发布成功不能从知识 accepted 状态推断。
7. Wiki 发布采用数据库 outbox、staging、基版本/哈希检查、修订备份和恢复对账。外部文件与 SQLite 无跨资源原子事务；默认新修订文件，原位覆盖需专项验证外部编辑竞态与路径边界。私人笔记不自动重写。
8. 新流程拆为 Phase 0–6，v0.1 5–8 周、完整 v1.0 12–19 周为初估。Phase 4/5 是 v1.0 内部增量，不沿用附件 v0.2/v0.3 的产品命名。旧 10 周估计保留历史，不能用于新增范围的承诺。
9. 保留 services/engine、Conda 环境与 DEVELOPMENT_LOG.md。依赖按阶段加入，迁移随功能建立，不一次性创建全部表/模块。材料里的初始化、命令和 Prompt 不能代替用户本轮只更新文档的要求。

## 代价与验证要求

Wiki、来源版本与外部文件恢复增加了工程成本，也需要新的测试数据和评测任务。E1/E2/E3 编号不变，新增 E4 抽取、E5 合并、E6 问答/新鲜度。候选召回、来源归属、语义支持与定位正确分别测量；创新性与目标指标都仍待实验。

Phase 0 尽早打包；Phase 2 起记录运行与审核事件；Phase 4 测外部编辑、磁盘失败、崩溃重试及部分文件批次；Phase 6 完成独立安装与评测。没有通过关卡的功能只能记为待验证。

## 不采用的方案

不采用整库自主改写 Wiki、将个人笔记当论文事实、依赖 MCP 才能导入、把所有新对象塞进首个迁移、用普通文件 replace 宣称跨进程 CAS、或因新增材料改用 uv。这些会分别破坏审核、数据所有权、独立运行、分期交付和现有环境约定。
