# ADR 0004：G0 放行与 Phase 1 首轮交付

日期：2026-10-29（Asia/Shanghai）。状态：用户决定已接受。

用户明确要求“默认 G0 通过了并开始 Phase1 的开发”。因此 G0 在流程上按用户决定放行，不再阻止 Phase 1；这不是新增的干净机实测结果。Phase 0 的本机和 CI 成功记录保留，无开发工具的 Windows 10/11、缺 WebView2 的实际验证仍未执行，后续发布验证中补测。

Phase 1 首轮实现 RG-006 的可运行增量：原生选择 PDF → 引用或明确托管复制 → 持久化 Job → 有界子进程解析 → 来源/修订/文本块 → 桌面查看。沿用计划指定的 PyMuPDF、SQLite/Alembic 和 Conda，不引入模型或 Zotero。

- 单任务最多 50 MiB、300 页、200 万提取字符、120 秒；队列单并发。取消和退出终止本轮解析子进程，结果只在任务仍为 running 时事务提交。冻结版实测发现 multiprocessing 启动路径不能完成解析，改为引擎自身的内部 `--parse-pdf/--output-dir` 子进程模式，stdin 与宿主配置通道隔离。
- 迁移 0002 保留 0001 项目和任务，升级前 SQLite backup。Paper/AttachmentRevision/Chunk ID 为 UUID；同项目相同文件哈希复用附件版本并保留来源映射；同一原路径内容变化追加版本，历史文本块不改写。当前只保留原始提取文本，不提前做断词、空白归一化或语义分段。
- 托管文件由所解析的同一字节快照生成；先落盘后提交数据库，数据库提交失败最多留下未引用缓存，不留下指向不存在文件的记录。异常硬退出后的未引用缓存清理、实时来源可用性检测在后续增量补齐。
- 页索引从 0 开始，UI 页序加 1；PDF page label 单独显示，不将其宣称为已核实印刷页码。bbox 是 PyMuPDF 文本块坐标；本轮没有精确字符高亮或科学证据审核。

RG-007 的证据对象、多 span 跨页引用、归一化映射、人工校正，以及 M1 完整验收尚未完成。首轮自造样本只验证工程路径，不代表真实科研论文解析质量。PyMuPDF 的许可证及依赖分发材料应在正式发布前继续核对；本轮不替用户选定项目开源许可证。
