# ADR 0006: Job History and Temporary Workspace Recovery

日期：2026-10-31（Asia/Shanghai）
状态：已采用，作为 Phase 1 RG-006 增量的实现约束

## 背景

PDF 导入和来源检查都在独立子进程中运行。宿主异常退出时，解析结果、来源附件和历史原文必须保留，同时暂存目录不能无限积累。项目任务历史还需要在新任务进入、任务重试和同一时间戳下保持稳定的分页边界。

## 决定

1. 只回收 `data/import-work/` 下由本应用创建的、直接子目录为 UUID、包含精确 `workspace.json` marker 的普通目录。目录链接、junction、未知 marker、非白名单文件和非平面内容均保留；不会递归扫描或删除 `attachments/`、原始 PDF、SQLite、备份或历史文本。
2. 每个工作目录使用同名旁侧 `.lock` 文件作为稳定租约。子进程取得 `FileLock` 后才读取或写入，启动回收使用零超时锁；活动进程计为 `busy`，迟启动的子进程在再次校验 marker 后失败，不会复活已回收目录。锁文件本身不包含文档内容，可以保留。
3. 清理按白名单逐项删除，最后删除 marker 和目录。任何权限、占用或其他删除错误保留 marker，并在下一次引擎启动重试；已提交的任务结果不因清理失败退回失败。健康接口和设置页报告 `removed`、`busy`、`retained`、`errors`。
4. Job 只记录实际阶段：`starting`、`reading`、`parsing`、`checking`、`saving` 或诊断专用的 `diagnostics`。阶段是提示信息而非百分比；重试清空旧阶段，取消或失败保留最后观察到的阶段以便追踪。
5. 项目任务历史以 `(created_at DESC, id DESC)` 排序，并在第一页固定 SQLite `rowid` 快照上界。`next_cursor` 是不透明快照令牌，包含页锚点和该上界；即使新任务与旧任务创建时间相同、UUID 排在页锚点之后，也不会混入后续页。状态变化和重试不改动创建顺序。游标锚点必须属于当前项目，否则返回 `INVALID_CURSOR`。

## 取舍与影响

该边界优先保护来源原件、托管附件和审核历史，代价是未知或权限异常的暂存内容需要人工处理。回收统计可见但不承诺一次清空所有临时文件。阶段不提供虚假进度，前端需要接受短暂的 `null` 或最后阶段。快照 keyset 分页比偏移分页稳定；调用方应原样保存并继续传递不透明游标。

## 验证

Python 单元/集成测试覆盖锁竞争、迟启动、目录链接、未知内容、权限失败重试、结果提交后清理失败、阶段文件共享失败、旧 Schema 0003 升级及游标边界（包括同时间戳迟到任务）。此前原生报告声称可加载 13 条历史任务；后续复核发现 Tauri 白名单错误地把 Base64URL 游标按 UUID 校验，该原生分页结论已撤销。白名单修复及 Rust 回归测试通过，但修复后的原生分页复测尚未完成。独立原生数据中其余旧库升级、取消/重试、回收统计和自造 PDF 原文重启读回按此前报告保留。外部干净 Windows、缺失 WebView2 和本轮安装 CI 结果不在本记录中冒称已通过。
