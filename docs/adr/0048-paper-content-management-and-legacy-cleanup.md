# ADR0048：论文内容管理与旧解析清理

- 状态：已实施
- 日期：2026-11-18（Asia/Shanghai）

## 背景

模型优先导入在 `lite0011` 中独立保存模型章节、公式、表格和后处理输出。旧库仍可能有基于本地 PDF 提取的 Chunk、FTS、结构解析和阅读投影。桌面需要明确区分两套数据，并允许用户管理论文及修订模型生成文本。

## 决策

- 新建项目和导入论文使用原生模态 dialog，限于当前视口并在内容过长时内部滚动。
- 同一论文存在模型导入会话时，概览、精读、章节材料只读取该会话的模型解析及后处理结果。旧本地 revision 不进入这些视图，也不触发旧 Chunk/章节读取。
- 论文题名可编辑；模型章节中的正文、公式和表格，以及已成功的概览、精读、翻译输出可在保存前按现有 DTO 重新校验。
- “清理旧解析”只删除该论文的本地 Chunk、FTS、EvidenceSpan、DocumentParse、阅读投影及旧 `LiteCacheEntry`。保留 Paper/Revision/Source、Section 锚点、笔记、生成的概览/精读/导读/问答/翻译、个人阅读状态、Token 用量、ImportSession 与 `llm_document_*`。
- 清理前生成并完整性检查 SQLite 在线备份。Revision warnings 写入清理标记；普通阅读请求返回 `LOCAL_CONTENT_CLEARED`，不得自动重建旧解析或阅读投影。用户显式选择“重新整理本地阅读版面”并成功发布后，才清除此标记。
- 删除单篇论文同样先备份数据库，再移除论文关联的数据。只有最终路径直接位于应用 `attachments` 目录的托管 PDF 可以随记录删除；引用文件、Zotero 原件、目录外文件和符号链接不删除。整个研究项目不随单篇论文删除。
- 清理和删除都由用户逐篇确认，不在启动、迁移或安装时批量擦除数据库；不读取或升级正式用户数据库作为开发测试。

## 验证边界

管理 API 在 `tmp_path` 隔离数据库中验证备份、外键顺序、生成笔记与模型内容保留、清理标记和托管文件路径约束。桌面回归验证题名刷新、清理/删除确认和模型会话下旧数据不进入工作区。未覆盖的真实 Provider 科学质量与原生 GUI 体验仍按 `docs/progress.md` 单列。
