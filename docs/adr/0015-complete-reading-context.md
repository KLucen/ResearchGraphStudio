# ADR 0015：完整整合与选择上下文

日期：2026-11-03（Asia/Shanghai）。状态：本轮实施；R5 可靠性与全文质量范围，实际验证见 [progress](../progress.md)。Alembic head 0011、领域及现有 Prompt/Schema 不变，未进入 P4/P5。

## 问题与目标

P02 移除固定 6000 字符/48 证据目标后，`reading_pipeline.py` 的后续阶段仍保留独立软件预算：P12 为 26000 字符候选、24000 字符证据、60 候选、8 根/窗口、20 窗口；P13 为 8 单元/批和 48000 字符。P13 的长度检查会在抽取/整合已成功后直接阻止选择，增大模型输出额度或重抽 PDF 无法修复这一调用前门槛。

本决策取代 [ADR0009](0009-reading-pipeline-implementation.md) 对新整合/选择计划规定的软件字符及数量预算；历史执行记录、旧 Prompt/Schema、原任务计划及已提交结果保留。

## 新计划：complete-context-v1

1. 新 `reading_finish_plan` 记录 `context_policy=complete-context-v1`，继续冻结来源/候选快照、Prompt/Schema、模型参数与 expected revision。
2. P12 用一个窗口输入本篇全部当前有效候选及它们引用的完整 EvidenceSpan 文本、已有合法关联和覆盖缺口。不再按固定字符、候选数、根数或窗口数删减、拒绝上下文，不裁剪表头、条件或证据正文。
3. P13 一次输入全部已验证结论单元、根、成员、质量/限制与密度信息，不再用 48000 字符或 8 单元的软件预算阻止请求。
4. 真实端点的上下文/输出能力、响应与总时限、网络重试及取消边界继续生效。不能把移除软件预算理解为无限上下文、无限输出或无限重试；真实能力不足应给出明确原因并保留成功阶段，不能静默截断材料。
5. 领域 Schema、证据白名单、归属/条件、合法端点、单元闭合、统一 KnowledgeStore、原始 ModelRun 及审计不放宽。模型仍只输出提案，不能覆盖已保存科学语义或产生数据库/文件操作。

## 冻结计划与费用保护

旧 `reading_windows` 必须在构造新输入前读取，存在时原样复用，包括原窗口、缺口及相应检查点键。不能先经过新构造或旧预算检查而阻止本可恢复的旧阶段；不为改策略重跑已成功 P02/P12。

没有 complete-context-v1 标记的旧 finish plan，P13 继续原 8 单元分组，保留原输入与检查点身份；只移除 48000 字符调用前阻塞，以便已有成功 P13 批继续命中缓存。新计划才将全部单元组织为一次请求。候选快照或签名发生真实变化仍按冲突处理，不能伪装同一输入。

失败继续使用已提交操作与可完整重验响应，原 Job/ModelRun/原始响应保持；整合或选择失败不重新抽全文。不将未报告的供应商费用写成零，也不为验证新策略盲目重复收费请求。

## 验收与限制

针对性测试应覆盖：超过原 P12/P13 各预算仍带完整上下文；新计划一窗/一次；旧 reading_windows 优先复用；旧 P13 分组和已成功检查点命中；成功 P02/P12 零重跑；非法引用/条件/单元仍拒绝；真实超时或端点容量不足保留知识并有界停止。

完整上下文可能增加单次输入量、延迟与费用，也受现有 DTO 和真实模型服务能力约束；本决策不宣称无限规模、真实科学质量或所有论文单次整合已验收。自动化回放、真实模型调用、全文质量与安装体验分别记录。无人工审核步骤，私人材料/运行库/响应不入源码，未经新授权不 Push。
