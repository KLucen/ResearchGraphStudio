# ADR0063：文字生成按可观察活动计时

日期：2026-11-21（Asia/Shanghai）

状态：已实施；实际验证见[本轮报告](../text-activity-timeout-verification-20261121.md)。

## 问题与证据

知识任务安全metadata只读诊断显示：普通等待配置90秒、派生总时限180秒；HTTP200及首字节约1.016秒到达，第179.938秒仍收到网络流数据，公开推理增量累计77935字符、最终正文0，约179.985秒按total超时。确定由旧固定总时限停止等待，而非180毫秒或连接超时。旧记录没有最后一次实际生成的独立时间，不能仅凭最后网络字节断言最后一刻仍有新推理或已经停滞；新策略因此区分实际生成与心跳并分别记录时间。计数不是Token、科学内容或费用证明。

## 决策

1. 新增`ModelParameters.text_timeout_policy: activity | legacy | null`，默认null兼容旧设置；`snapshot_for`只为新任务将null或缺字段冻结为activity，显式legacy保留。`from_snapshot`消费已有冻结快照，无字段/null仍沿原固定总时限，不回写历史或用户配置。数据库无迁移，head仍lite0018。
2. activity文字请求没有固定总deadline。连接独立最多15秒；HTTPX继续约束连接池、上传/网络读取停滞。请求体发送完成后开始等待首段可观察生成，正文或公开`reasoning_content`/`reasoning`字符增长时重置无活动deadline。等待秒数使用`timeout_seconds`，仍为5–180秒整数；不是整个生成必须在该时间内完成。
3. SSE注释心跳、空delta、role或usage事件不重置生成计时。正常`[DONE]`关闭传输，并仍验证结束原因及完整协议；不能因为网络一直有保活字节而无限等待无内容任务。非SSE兼容响应只能观察非空白数据接收进展，单独记录`response_bytes`活动，不记作正文/推理生成，空白保活不续期。
4. 超时区分连接/发送、首段生成、生成停滞及非流式数据停滞；metadata记录安全计时/活动种类和字符计数，知识任务诊断仅输出固定说明及白名单数值。公开推理只计长度，不保存或展示推理正文。取消、超时和断线均关闭异步socket，保留已有合法成果与失败/私有片段，不自动重发或把片段发布。
5. 文字设置显示activity推荐与legacy兼容选项。文档请求继续使用独立600/1800秒设置和既有有界策略，不因文字policy移除总时限。资源大小、Schema/引文/来源终验、联网授权与显式重试槽保护不变。

## 限制

只能观察供应商实际公开的增量或响应数据，无法查看服务端隐藏思考、排队或GPU执行状态。不发额外模型请求探测“是否还在思考”。服务不公开推理或缓冲完整正文时仍可能在首段等待超时；用户可在范围内调整等待秒数。内部监测不承诺供应商永不超时，也不等于实时向UI持久化每个Token。真实模型和科学质量验收与合成流测试分开。
