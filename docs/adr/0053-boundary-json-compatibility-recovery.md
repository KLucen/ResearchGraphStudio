# ADR0053：边界JSON模式兼容修复与一次受控恢复

日期：2026-11-18（Asia/Shanghai）。状态：已实施；真实服务修复后验收待用户执行。

## 证据与原因

用户报告分页解析HTTP400，明确继续仍400。本轮仅用SQLite mode=ro/query_only查询任务时间、冻结非敏感参数、批次计数与安全request_metadata，没有读取正文、模型材料、原始响应或凭据，没有重发收费请求。2026-11-18 21:25:53.934–21:25:55.175最新请求约1.218秒返回400。正文3个抽取批次均已validated/HTTP200，核心原页1–5、6–9、10–13；失败在第5–6页第一个边界，已显式尝试3次。

边界分支替换提示词后遗漏JSON字样，但保留response_format=json_object。抽取与格式修复提示包含JSON，所以能越过相同限制。火山[结构化输出官方文档](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=en)说明，Chat API启用JSON Object时输入应包含json字符串。合成MockTransport在缺失该要求时复现400，两条传输修正后单请求通过。旧版未保存400错误正文，不能声称已见服务方具体错误原文；任务阶段和代码缺陷强匹配，不把可能因素当已观测服务消息。

## 修复与恢复边界

- boundary明确要求有效JSON对象；保留原Schema、冻结模型、文件/图片路线与严格验证，不自动切模型、取消JSON模式或重发。boundary_prompt_version=2为纯数值诊断。
- 正常每批最多3次显式执行不变。仅所有extract已validated、未完成项均为旧版boundary HTTP400、尝试1–3次且从未使用修正版请求时，提供兼容恢复。已耗尽3次的旧boundary可再显式发送一次；不清零attempts/request_count，不改旧账本与材料，不自动排队。
- 修正版槽位在POST前同事务写usage.requests及版本标记，包括之后崩溃/超时。已发送修正版后不再享受兼容例外；第4次仍失败后继续被409拒绝。发送前取消/本地预检失败没有新增槽，保留旧HTTP400元数据与恢复资格。原源版本/冻结快照/范围仍须重验。
- Job详情、项目历史和全局历史在只读GET派生compatibility_retry_available/current_kind，不回写任务/检查点；按钮只有明确true才为耗尽任务提供“确认继续边界复核（可能收费）”。
- UI分开正文批次与边界进度，展示安全HTTP状态；重复400提示检查参数或更新修复版，不暗示继续可以自动修复请求。完整错误响应仍不展示、不落日志。

本决策只修请求兼容和本次已知旧边界恢复，不允许无限重试、不把客户端400当内容契约失败送格式修复，也不重新解析已成功正文。真实调用仍由用户安装后明确确认，可能产生费用；不要求重新导入论文。
