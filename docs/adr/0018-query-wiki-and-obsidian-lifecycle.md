# ADR0018：图谱驱动的 Query、Wiki、Lint 与阅读知识沉淀

日期：2026-11-03（Asia/Shanghai）。状态：P4/P5 设计决策，待实现；不改变当前 head0011、运行 Schema/Prompt 或用户文件。补充 [ADR0008](0008-reading-knowledge-graph.md) 和 [阶段计划](../06_development_migration_plan.md)。

## 背景

当前可见知识图谱是结构化论文知识的投影视图，不是 Wiki。P4/P5 上一版计划虽提到文档依赖，但把 Wiki 检索放在 P5 之后，未充分说明 Query 如何读取文档状态、问答保存到哪里，以及 Obsidian 文件被用户编辑后的职责。需要避免“只查图谱”“保存答案就改论文主张”及数据库/Markdown 双向静默覆盖。

本轮补清知识图谱在完整流程中的实质作用：它组织结论、支撑和有据关联，为Query扩展上下文、Wiki组织主题及Lint检查依赖提供共享结构。GraphProjection是画布投影，不能把“投影不是检索全集”误解为图谱只负责可视化。开发计划和[项目介绍流程图](../../README.md#从论文到阅读知识)据此同步，本轮仍仅改文档。

## 图谱消费的共同约束

- Query从文本/术语/Wiki命中点出发，沿完整合法单元和科学关联补齐方法、实验、条件、结果和限制，记录路径、修订和根证据；没有图谱关联时允许检索原文和未选候选。画布分页、折叠、隐藏不限制检索，旧Comparator的3跳/100节点/48K字符约束不直接继承。
- Wiki按问题或主题组织相关结论单元，保留跨论文共同点、分歧和适用条件，再补必要原文/候选；不能简单把每个节点改写成一个段落。每段依赖可回到根证据。
- Lint分别检查来源锚点、图谱支撑/关系合法性、综合/文档的版本依赖及文件同步。布局变化不触发科学失效，单元共享或相邻位置不代表科学支持。
- 明确保存的Synthesis/Insight是衍生知识，引用原结论与证据，可在独立图层显示；该图层关闭不影响已保存内容检索。引用关系不是论文作者的新Claim或新科学关系，Query临时推断不自动写边。
- 导航边、科学关系、衍生引用和文档依赖分型；NO_DECISION不形成科学边。来源ID存在仅证明引用身份可核对，不证明科学推论正确；模型推断保留归属和不确定性。
- 同一Store支持这些消费，执行日志、文件扫描、Lint诊断与科学修订分离。现有Store.event/Obsidian扫描会推进GraphRevision，P4-Q01应先解决此耦合，不能让普通读操作破坏画布分页。

## 决策一：同一底座中的不同对象

| 对象 | 内容与权威范围 | 持久化与展示 |
| --- | --- | --- |
| 来源与结构化知识 | 原文/证据、作者主张、方法/条件/结果、来源关联；作者主张不等于科学事实 | 同一 SQLite/KnowledgeStore；知识图谱是其中一部分对象和关系的视图 |
| 已保存阅读综合 | 用户明确保存的有据解释、跨篇综合或个人观点；保留归属和原 Query 来源 | 同库的衍生对象及版本化段落依赖；可被 Query 检索，不伪装为论文作者 Claim |
| Wiki | 按论文、概念、方法或比较组织的阅读文档，含有顺序的段落、引用、条件和限制 | 同库的文档/段落版本、依赖及状态；可引用已有知识和阅读综合，正文是文档表达，不建立平行科学知识库 |
| Obsidian Markdown | Wiki 的授权文件载体，以及独立存在的私人精读笔记/外部文档 | 磁盘当前字节决定文件是否被改；数据库保存最后受管版本、文件身份和 hash，不能以旧数据库副本覆盖用户当前文件 |

Wiki 既不是画布上的节点集合，也不等于任意一份 Markdown。没有 Obsidian 时，内部 Wiki 仍能保存和检索；有 Markdown 也不能仅因文件名或 frontmatter 就信任其科学来源。

## 决策二：Query 同时消费 Wiki 内容、状态和底层来源

P4 的共享契约/索引任务先实现最小文档登记、只读快照和状态过滤接口，接入已有受管 Wiki（若存在）和授权外部文档；P5 再补完整 Wiki 生成、渲染、可靠发布和增量更新。没有 Wiki 时仍可直接读有效结构化知识与原文，不形成 P4 必须等待完整 P5 的循环依赖。

Query 先定位相关文档段落与结构化知识，再核验版本/权限/根证据并补充原文、未选候选和条件。Wiki 可提供组织与历史综合，但不能取代科学证据；没有直接命中 Wiki 也不能据此判断项目没有相关知识。页面、已保存综合和其引用的同一论文不能算作多份独立支持。衍生依赖不得形成自引用或循环“证明”。

状态分两个维度，不压成一个“已发布/未发布”标志：

| 维度 | 拟定状态 | Query / Lint 行为 |
| --- | --- | --- |
| 内容与来源 | 当前有效、依赖已变/过期、来源失效阻塞、来源尚未验证；文档另有草稿/保存版本 | 默认回答只使用授权且依据仍有效的已保存版本。过期或未核验段落用于解释缺口，不作为已核验论文结论；可回到底层有效证据重新回答 |
| 文件同步 | 未导出、与登记版本一致、外部修改、文件缺失、发布冲突 | 未导出/文件缺失不自动否定内部有效内容；外部修改不自动替换内部正文。展示使用的是内部哪一版本及磁盘差异，不能声称已读到或同步了外部最新编辑 |

检索须按段落评估，不因一个条件段失效就删除全页，也不能因页面其他段有效而放过失效段。文件冲突时可使用仍有效的内部保存版本，但必须明确其版本及冲突；不能把未登记的外部新段落当作同一受管版本。仅选择/密度改变提示组织可能变化，布局改变不影响科学内容。普通草稿和未保存答案不自动回流检索；查历史的操作与当前可用科学依据区分。

Query 不依赖“上一次 Lint 没报错”来判断当前状态：读取文档登记/依赖修订，使用外部文件前按授权获取最新快照/hash，发送模型前再查权限和上下文。文件读取失败记未知/不可用，不能判文件未改。历史保留不使撤销授权的资料通过缓存或综合继续外发。

## 决策三：Query 保存与修改论文、Wiki 导出分开

1. 提问只产生执行记录和临时回答，不变更论文知识或文件。
2. “保存为阅读知识”创建有类型的 Synthesis/Insight 等衍生对象，保存原回答、所选段落、归属、模型记录和版本化依据，经 KnowledgeStore 幂等写入。同一次保存不会改写作者主张、数值、证据、核心选择或既有用户语义。
3. 默认在“已保存阅读综合/问答”中查看；图谱可用独立衍生层显示其与来源知识的引用关系，不自动挂成论文作者核心结论，不复制原 Claim。是否展示是视图选项。
4. “整理为 Wiki”可创建新文档版本，或对用户选定受管页面形成局部更新；没有目标页面时不猜写入位置。只有请求明确包含“更新此 Wiki”才改变该文档，原版本保留。
5. “导出/更新 Obsidian 文件”是独立的授权写入动作。可以在一个明确操作中选择“保存并导出”，内部仍分别做知识/文档提交与文件发布恢复；不能因为问题里有“记下来”就让模型任意找文件覆盖。不存在先人工科学审核再保存的关卡。

阶段边界：P4-Q07的文档目标只允许将明确保存且已终验的段落登记为内部版本，比较目标基线并保留旧段落；不调用P10/P11或渲染/发布Markdown。P5再实现主题整理、模型局部重写及文件发布。“保存并导出”为完整P5具备后的明确组合动作，不是P4必须提前完成全部Wiki的要求。

新增衍生知识推进相应语义/依赖版本；纯文档排版、导出hash或执行诊断使用各自版本，不让全部论文图谱因此失效。具体 revision 分配在 P4-Q01 冻结，不能直接把当前 Store.event 当作通用日志入口。

## 决策四：Obsidian 内容分受管文档与外部只读材料

受管文档必须通过应用登记：项目、授权 root、程序生成的相对路径、page/section 身份、最后发布版本和 hash。frontmatter/段落标识帮助定位，但磁盘自报的 ID 不是授权或来源证明；一份外部文件不能仅靠拷贝 ID 冒充受管页面。

- 受管 Markdown 未改且依赖有效：可按内部文档版本检索、检查和更新。
- 受管 Markdown 被外部编辑：读取为新的只读文件快照，显示 diff 并阻止旧草稿覆盖；保留用户原文件。新编辑不自动变成论文 Claim 或已验证 Wiki 段落。用户可明确选择把编辑登记成新的文档/个人观点版本，仍执行引用、归属和权限校验；也可重新导出到新文件，不增加科学审核队列。
- 私人笔记/未登记 Markdown：仅在授权读取及相应外发范围内作为外部资料检索或检查。没有绑定论文证据时按个人/外部资料归属，不能伪造证据。Lint 不能仅凭缺少系统元数据就判私人笔记错误，更不能改写它。

文件重命名/删除/零字节/只读/同名等必须能诊断。内容相同可给用户关联候选，不能据此默默获得新路径写权。导出仅在明确授权的受管目录执行，发布前再次检查身份、base hash、权限和路径边界；替换后未确认的情况由持久操作账本恢复。

## 决策五：Lint 覆盖知识、依赖、文档和磁盘状态

| 检查层 | 检查对象与方法 | 结果/动作 |
| --- | --- | --- |
| 来源/结构化知识 | 版本、hash/offset/quote、关联端点、支撑路径、归属和条件结构 | 确定性错误阻止相应对象作为新依据；不删除旧数据、不自动改科学数值 |
| Wiki/综合段落 | 引用白名单、根证据、版本依赖、个人观点/AI综合标识、循环引用、组织与语义变更区分 | 标具体过期/缺证据段落并定位；有效部分保留，生成有据更新建议 |
| 受管 Markdown | 最新hash与登记版本、段落映射、引用/内部链接、目标是否缺失、编辑冲突 | 给出文件差异与受影响段落，阻止覆盖；缺失/冲突不自动删除内部知识 |
| 外部私人 Markdown | 仅授权范围内的快照/hash、Markdown链接及显式可核对的引用 | 无足够依赖时标“无法核验”，不是“科学错误”；默认只读，语义检查及外发另选 |

确定性扫描为主，P09 模型只补语义诊断建议；不因不同论文结论不同就判断哪篇正确。检查不等于同步，不触发私人文件改写；“修复索引”“重新生成受影响段落”“更新导出”是不同操作。检查结果进入本地诊断状态，不变成审核队列。

## 必须落实的验收

1. 有效 Wiki、仅内部未导出 Wiki、一个段落过期、文件缺失、外部编辑/冲突、未核验私人笔记分别查询；断言使用的内容版本、来源归属、缺口说明和根证据，不静默混用文件与数据库两版。
2. 保存回答仅新增衍生对象，原论文 Claim/证据/核心选择和磁盘文件保持；再次保存幂等。指定更新 Wiki 时新增对应文档版本，未导出前文件仍不变。
3. Wiki 与其根来源同时命中不增加独立证据数，循环依赖拒绝；私人资料授权撤销后，保存综合/文档/缓存不能绕过权限。
4. 外部修改受管 MD 后，Lint 发现hash差异并定位，旧发布命令因base冲突停止；个人编辑不自动反写论文图谱，未受影响段落不重写。私人文件保持原hash。
5. 文件当前状态的检查、失效传播和发布故障恢复使用隔离Vault及合成数据；真实用户原件/正式库不用于制造故障。实施与实际成绩按 P4/P5 报告另记，本 ADR 不是已完成功能。
