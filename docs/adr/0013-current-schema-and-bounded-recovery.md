# ADR 0013：新版候选范围、Schema 闭合与有界续接

日期：2026-11-02（Asia/Shanghai）。状态：已实施，R5可靠性迭代；未进入P4/P5。

## 事实与决策

用户报告waiver(extra_forbidden)和拆分后超时，要求统一新版图谱。只读备份正式库后确认：最新失败是旧阅读Prompt的完整响应额外生成顶层说明，约26秒返回，非Token截断。另一超时是旧非流式/默认思考任务的历史记录。旧任务继续冻结旧Prompt，且原整合读取文献版本下全部新旧知识，导致升级与范围混用。

1. 原文、历史知识、任务和ModelRun不删除。新阅读候选须同时满足reading-1.0/P02_reading来源与当前Candidate DTO。旧unified图谱不进入正常阅读、候选搜索、P12/P13和默认图谱。选择/快照带candidate_scope；旧选择隐藏但revision继续递增，不重置历史。
2. 普通retry为旧生产模板创建独立新版任务。已有reading领域成功操作逐批继承；已收到且通过当前字段、来源白名单和文献/批次身份重验的响应可复制为零调用ModelRun。新旧Job/签名分开，原ModelRun保持。未完成部分采用新模板及当前模型传输策略；旧unified候选不冒充新版，不继续复用其旧图谱。显式测试保留历史兼容。
3. 新P02使用P02_reading_extract_compact_v2，传输仍reading-compact-1，领域仍reading-extraction-1.0。items/links必须显式存在；模型额度仍取实际能力和剩余上下文。未知字段、错误证据和条件不通过，不采用extra=allow。
4. 已观察的顶层waiver字符串仅保留到warnings，规则/字段路径记录审计。P12旧模板的warnings/limitations文字与Schema冲突：新P12_reading_integration_v2只要求warnings；新P13_reading_selection_v3只要求coverage_gaps。原限制说明映射到对应字符串数组；只有已知的冗余选择版本标记可记入审计后去除，对象扩展和未知版本仍拒绝。全部raw_output不改。
5. P12先预留窗口根，再加入支撑，不让UUID排序挤掉根。根的自成员引用只去除自引用并审计；并不当作自我支撑。窗口外组织建议、非法方向、不同归属/条件的重复建议分别隔离或拒绝折叠，保留候选独立性和失败原因，不替换ID、不创造关系。实际写入仍由Store检查证据与闭合路径。缺少根整合结果时仅保留直接依据单元并标缺口，不捏造科学内容。
6. 旧错误保留在历史，新续接显示Schema升级；不再把过去90秒超时误认为新请求失败。连接、无响应、总时限和有限拆分均保留，不无限增大timeout或自动重发。阶段检查点及收到的合法结果可续用。

## 版本与兼容

没有新增数据表或Alembic迁移，head仍0010。传输表示/领域Schema/数据库版本互相独立。旧节点详情、模型原始响应和兼容API可读取历史。正常知识列表请求current_schema_only=true，历史API默认行为保留。

已有reading-1.0候选并非旧unified图谱；其语义与严格DTO不因紧凑传输升级而失效，可节省已成功调用的费用。用户要求不使用旧图谱，不等同于删除原始资料或历史记录。

## 实际验证与限制

真实副本9/12→12/12，waiver响应零调用恢复；两次新增P02约25/19秒。发现并修复整合窗口排序、外层说明和组织建议问题后，发布22核心单元，重开后默认23节点、展开28节点/29边，所有节点来自新版范围且边闭合。原422知识、48模型记录、9任务、934证据及来源表逐行不变。最终P13模板另做8根真实窗口验证，无需归一化。

结果为partial：表格上下文及支撑仍有缺口，展开仅有3个Method和2个Concept支撑，不宣称全文知识质量已达标或另一篇已验收。完整命令、累计费用范围及安装器见[本轮验收](../archive/reports/schema-scope-verification-20261102.md)。
