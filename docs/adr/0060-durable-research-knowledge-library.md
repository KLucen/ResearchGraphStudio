# ADR0060 — 可长期维护的研究内容知识库

日期：2026-11-20（Asia/Shanghai）。状态：K1–K3已实施，整体交付状态见[本轮验证](../knowledge-library-verification-20261120.md)。用户明确授权按[实施方案](../research-knowledge-base-plan-20261120.md)完成前三阶段、闭环回归并上传GitHub；本轮不自动执行收费模型验收，K4未启动。

## 目标与工作空间

在“研究项目”和“任务记录”之间新增“研究内容知识库”，使论文知识、来源和历次联系汇报独立于阅读工作区保存。一个个人库，通过项目和专题筛选，不建立虚假研究项目承载用量。三个视图为“知识地图 / 论文知识 / 联系汇报”，保留上次选择；地图初始显示题名根，展开论文后显示问题、概念、方法、作者贡献与结果。论文归属线与AI跨论文虚线区别显示，跨篇同名节点不自动物理合并。

现有概览可零模型收藏，标为legacy/缺少逐项原文定位，不参与新科学联系发布。新带来源版本标为grounded，含义是来源可回查，不是科学正确已证实。个人备注、归档、专题、已读/置顶和布局是用户管理数据，不覆盖AI分析或论文原话。地图与汇报支持双向定位、查看双方摘录及返回实际项目论文；浏览、搜索、切页、拖动和重开不触发模型。

## 身份、快照与生命周期

`lite0016`增加个人库、论文条目、多项目来源链接、不可变知识版本、专题和独立视图；`lite0017`增加建模运行与持久发送状态；`lite0018`增加关联运行/请求槽/版本对检查点/汇报/事件及删除后的用量墓碑。迁移为加性、升级前备份，不回写旧解析/精读/译文或旧Prompt。

应用paper ID是来源身份，library paper是长期条目；已知合法SHA-256和真实Zotero库/条目/附件身份用于合并来源链接，同题名不能合并。未有文件哈希的模型稿不会为入库强行重读PDF计算全文件哈希。知识版本包含source_kind/source_id、来源manifest与指纹、合同、联合输出、模型/任务关联及snapshot hash，正式节点ID由程序绑定；不同版本的节点不当成一个全库实体。

画布题名根为`paper:{library_paper_id}`，归属边为`HAS_KNOWLEDGE`。前端把展开节点限定为`version:{version_id}:{node.id}`，独立画布布局不覆盖原概览布局。来源链接以应用paper删除时SET NULL脱离；独立冻结知识快照继续可读，并显示原项目论文已移除。重新生成创建新版本，失败保留旧成功版本；用户可显式采用已保存版本。依赖非当前版本或已归档条目的旧汇报保留并标“依据旧版本”。

归档排除后续比较但不删文本。独立永久移除入口有明确确认和数据库备份，删除相应知识版本、涉及的关联/汇报/请求raw及含内容的幂等副本；原项目论文保留。活动建模/关联依赖存在时拒绝永久移除。删除后保留无原文的消费墓碑，不能通过删除重置累计预算。备份属于明确的本机恢复材料，不上传GitHub；它不等于当前库仍保留已删除内容。

完整JSON导出同时包含知识版本、专题、报告及独立布局，报告的已读/置顶/个人备注随导出保留；导出前重验报告依赖/原始冻结结果，损坏报告拒绝。不导出模型原始响应、凭据或模型配置。

## K2合同与来源边界

新增独立`paper-knowledge-1`联合生成PaperCard与五类图，不替换旧`PAPER_OVERVIEW_WITH_LIGHT_GRAPH_V1`。模型只输出局部知识、关系和来源短编号/精确引文；正式ID、论文题名根、归属和来源定位由程序生成。非PAPER节点及科学关系必须有非空`source_refs`，引用格式包含source_id、exact quote及occurrence_index；严格JSON拒绝重复键/非有限数，DTO和实际来源再验通过才发布。PAPER根及归属线不冒充科学依据。

本地adapter读取完整已保存reading projection及实际span/chunk范围；模型adapter读取所选成功parse的实际segments及版本/locator，明确是模型提取材料，不伪造成PDF逐字真值。References、目录和页眉页脚不进入建模；无PDF重读、上传或OCR。模型稿缺页码时保留null，公式/表格语义未知不推断数字或比较优劣。生成前、收到后、缓存复用和发布均核对来源，漂移停止，不靠再收费“修复”来源。

当前K2是完整材料单次请求，已知输入/输出容量与库策略在占发送槽前预检；容量不足整体拒绝、零发送，不静默截断、自动拆批或降级重发。单运行持久一个请求槽；相同解析输入累计最多2次显式发送，更换模型不重置上限。固定坏响应保留本机私有raw，不自动修格式或请求后继；合法received raw可显式本机重验恢复，零网络。相同成功输入复用前重验raw、输出和已保存来源版本。联合卡片/图保存在新知识版本中，不承诺覆盖原概览历史。

## K3策略、候选与汇报

新增模型用途`knowledge_extract`和`knowledge_connect`。默认auto_collect/auto_connect/allow_network均false，同项目范围；auto_collect实际指“后续解析完成后自动构建带来源知识”，会使用模型，界面明确区分零模型收藏。启用任一自动策略须明确允许在范围/预算内发送材料；策略保存不回溯扫描无事件的旧源。

解析成功发布与KnowledgeCollectionEvent同事务持久化，提交后进程中断仍可在重启派发一次K2，不重解析、不重复建模；事件保留冻结来源和策略，派发时也取当前更小预算并检查撤销授权/缺模型。只有排队时已授权自动关联的新知识版本发布才创建持久分析事件；生成过程中开启策略不扩大旧任务授权。已成功建模但关联失败时知识仍保留；取消、失败和已发未知结果不自动循环重发。

策略默认候选8篇（1–50）、每次关联最多2请求（1–8）、输入48000/输出6000 Token及累计20请求，数值可调。累计请求包括建模和关联已发槽位、活动预留及消费墓碑，超限暂停待处理，不能静默扩预算。独立`/knowledge/usage`显示实际已记录调用/Token和费用未知；规划估算不当成实测usage。候选/图谱浏览页与关联范围独立。

候选召回使用已保存当前非归档知识的英文词及中文二元组，冻结实际项目/专题/全库范围、候选版本、排序策略、完整来源与模型/策略。不等于向量语义检索或全库逐篇深比；legacy排除计数单独记录。无候选也保存no_candidates报告，零模型发送；词面未召回不证明不存在联系。关系类型为SAME_PROBLEM、RELATED_CONCEPT、RELATED_METHOD、COMPLEMENTARY_METHODS、COMPARABLE_RESULTS、RESEARCH_OPPORTUNITY。

关联DTO只引用冻结双方科学节点及各自已验证来源，程序绑定双侧ref.source；解释与limitations_zh必须有值。总结段必须引用已发布关系ID；无关系原因单独保存，不发布无来源科学断言。一个结构化响应同时提供关系和总结，不再强制调用模型写汇报。coverage保存eligible/selected/compared/not_compared/excluded_legacy/scope，部分批次失败标partial，成功检查点可保留续接。引用和条件合法不证明关系科学成立，semantic_accuracy保持unverified。

完整相同输入复用运行；无序知识版本对检查点避免A/B反向重复与并发漏比。旧检查点从冻结raw与来源重验；版本对缓存可跨新关联配置复用且零请求，不声称使用了新模型重新比较。只有显式force_regenerate才绕过版本对复用，创建新请求/新报告并受原预算与发送终验限制，旧结果保留。请求前先持久占槽，等待模型不占写事务；重启不会重复发送已发槽，显式继续只补可继续范围。

## 当前限制与后续

原项目论文仍存在但所选解析内容被单独清理时，新增关联会在来源重验时停止；已保存知识与历史汇报仍可读。删除整篇应用论文后则可按明确脱离来源的独立快照比较，此两种状态后续再统一产品提示。

K1–K3合成Provider/隔离库和真实浏览器渲染回归用于验证流程、来源、状态与调用计数；未执行真实收费模型或正式用户库实验，不能称科学质量通过。长文自动拆批、语义召回、跨篇实体聚合、复杂条件推理、100篇/1000节点规模和通用性能SLA留在K4；真实用户WebView升级/交互、干净机及受控真实论文科学样本另验。实际最终测试、包指纹、上传与CI以本轮验证记录为准。
