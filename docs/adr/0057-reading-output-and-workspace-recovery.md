# ADR0057 — 精读输出故障分类与统一论文工作区

日期：2026-11-19（Asia/Shanghai）。状态：实施，验证结果见[本轮报告](../workspace-fixes-verification-20261119.md)。承接[ADR0056](0056-unified-reading-from-parser-sources.md)。

## 问题与证据

用户反馈精读生成失败、WorldGraph论文回答提示引擎断开、两种解析来源的页签不同，以及部分论文缺少解析切换入口。中断现场已包含部分代码，但缺少完整校验和本轮交付。

正式库只读诊断显示两次精读失败没有可校验的响应正文，旧错误分类却声称原始响应已保存并建议格式修复。历史记录未保留实际传输失败类型，不能据此判定旧请求一定超时。WorldGraph有32页、65个章节和633块；问答原先为了显示目录读取全部章节正文。当前源码同一来源读取全正文6.911秒，仅读目录0.185秒；该测量不能证明当时已经超过宿主15秒时限。

## 决策

1. 区分模型传输、空响应、截断、契约校验、来源变化和存储失败。有真实失败正文时才说明已保留；只有契约失败且满足原始响应、来源和预算条件时开放显式一次格式修复。历史失败记录和原始响应保持，读取页面不触发模型。
2. 新的模型材料后处理计划冻结`postprocess_contract_version=3`。精读和译文只要求模型回传固定编号槽位的笔记或译文；正式段落ID、章节身份、原文和常量字段由程序绑定。完整槽位、严格JSON、逐字引文及occurrence和当前来源终验继续执行。旧v1/v2快照和修复沿原协议，不用新协议解释旧raw。
3. 新模型精读/译文使用冻结的文档生成时限，受原有配置上限约束，不用普通短文本默认时限截断长篇任务；这不是无限等待或全文成功保证。精读和译文仍分别生成，不额外上传PDF，也不自动增加请求次数。
4. 所有文本模型任务共用的传输层区分兼容JSON外壳、SSE正常结束、空正文、拒绝、工具调用和截断。用量缺失保持unknown；中断时已有用量回执仍保存。单次失败不自动降级、重发或付费探测。各业务契约继续拒绝额外字段、重复键和非法来源引用。
5. 论文回答先读取不含正文的章节目录，选中章节的原文按需读取，来源和版本仍逐次验证。Rust宿主区分本地请求超时与实际连接失败；超时提示重读，不把健康诊断显示的已连接改成断线。
6. 本地与模型阅读来源共用“论文概览、论文精读、论文回答”三个页签。模型章节原材料收在精读内可展开的材料区。论文回答继续使用本地来源索引；缺少本地解析时明确提示入口，不把模型提取稿冒充已验证的本地证据。
7. 各论文工作区都显示圆形“论文解析操作”按钮，展开本地解析/重试、查看本地解析内容、使用模型重新解析、查看模型解析内容四项。没有对应材料时保留入口并显示不可用原因。弹层支持Escape、外部点击和焦点恢复；切换来源不调用模型。

## 数据与验收边界

### 精读标记本地恢复补充

后续只读诊断确认一份已保留精读响应含不支持的精确类型名`CLAIM`，以及两处无法在对应段落原文找到的引文。中文翻译为独立任务，成功不代表精读标记通过；这类精读校验失败不得统称JSON格式损坏。

新精读使用合同v4，在既有v3固定slot wire格式中明确列出规范高亮类型及`THESIS`语义，并禁止模型输出`CLAIM`。译文仍使用原合同；旧v2/v3快照及raw不改。普通发布继续严格拒绝任意未知字段、类型、段落/slot覆盖或来源不匹配。

仅在用户明确点击本地恢复后，程序可将完全匹配的`CLAIM`改为`THESIS`，并隐藏引文或occurrence无法在对应原文验证的高亮。任何其它校验失败都拒绝恢复。隔离迁移`lite0015`把恢复后的精读JSON、来源版本及不含引文正文的规则审计存入独立本机表；原失败输出的状态、错误、raw和请求账本不变。GET重新验证当前解析版本，UI只显示标为`partial`的精读结果，独立成功译文仍单独读取；此路径没有Provider调用或费用。

正式库仍只读诊断，不重试用户任务或修改私人论文；测试与安装烟测使用隔离数据和匿名材料。真实模型请求、科学与翻译准确性、用户原生GUI和干净机结果分别记录，不把合成Provider成绩当真实验收。无新增Commit/Push授权。
