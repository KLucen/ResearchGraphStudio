# ADR 0029：Lint、Wiki 草稿与受管文件发布

日期：2026-11-05（Asia/Shanghai）。状态：实施中；本轮用户明确要求恢复并继续 P5，覆盖旧轮次“不进入 P5”的范围限制。实际验证与未完成项见 [P5 续开发报告](../p5-verification-20261105.md)。无新的 Commit/Push 或付费验收预算。

## 决策

1. 继续同一 Knowledge Engine、SQLite 与 KnowledgeStore，不重建工程。加性迁移 0015 增加诊断与依赖索引，0016 增加 Wiki 页面/段落元数据、写入授权与发布账本，0017 增加 P5 工作流/模型请求槽，0018 增加显式外部文档来源，0019 增加批注用途授权和最后显式导入的当前批注索引。旧 Query、阅读知识、ModelRun、原文、核心选择和布局保持。
2. Lint 的确定性报告和 P09 语义建议分开。检查来源、精确锚点、科学支撑、条件结构、文档依赖和文件同步；相同输入使用稳定问题指纹，保留新发现/仍存在/已消失/输入过期。诊断及重建派生索引只记审计，不推进 GraphRevision。私人 Markdown 无系统证据时标无法核验，不自动认定科学错误，不改原文件。
3. P09/P10/P11 使用独立 `reading-workflows-1` 运行 DTO 和 Prompt，保留旧参考模板及全部历史协议。由实际 Schema 生成规则与本次引用 enum；模型只输出建议、段落或局部编辑。拒绝重复键、NaN、未知字段、假引用、越出目标段落的更新和错误归属。条件四态不等同于通用科学核验。
4. 显式准备冻结所选论文的完整合法候选、原文、单元支撑和按用途授权的资料，不从画布或词面 top-k 取全集。来源不足或容量不足停止，不能裁掉条件/表头。P09 必须引用相同论文/个人资料范围的已完成规则报告。发送前、收到响应、GET、生成内部版本及保存均重新验证当前来源、权限、协议和基线。
5. 全局 Reasoning 模型只由显式 generate 入统一 Job 后使用。每工作流最多两个持久发送槽，超时计入；每个显式动作至多新增一槽，不自动格式重试或降级。完整 raw 先落盘再验证；可恢复响应在读取凭据/网络前复验，恢复失败也不偷偷退回新请求。可信输入变化只记复用诊断，保留历史响应状态；模型响应自身不合法才记 validation_failed。
6. 模型结果、内部草稿、已保存不可变版本、最后导出文件是独立状态。P10/P11 成功不自动保存或写文件。程序分配页面/稳定段落 ID，局部 patch 必须匹配 base 版本/content hash；未触及段落原样保留。Markdown 转义不可信 HTML/链接，保留引文、条件、Zotero 链接与覆盖缺口。全文版本 hash、段落 hash、侧表身份和当前依赖都须核对，不能信任缓存 Markdown 或 diff。
7. 写入目录由原生目录选择器授权，独立于笔记读取/模型用途授权；模型和普通 HTTP 请求不能指定任意输出路径。文件名由页面 ID 生成，仅写受管子目录。已有文件（含空文件）必须同时符合受管页身份、hash 和文件身份；同名私人文件、外改、链接逃逸、撤权或新旧草稿竞争停止。
8. 发布账本先登记 base/target hash，再同卷暂存、原子替换、数据库确认。各检查点可幂等恢复；恢复重新检查权限、来源、版本、目标及暂存身份。外部文本仅建立只读快照/diff，不继承旧 manifest，也不反写科学知识。文件缺失/外改与内部证据有效性分开。
9. 新 P5 请求显式冻结 `personal_sources/p5-personal-sources-1`，分别选择 note 快照、Annotation.comment 和外部文档版本；授权与选择是独立动作，授权不会自动选中资料。直接来源、文档传递根和 P11 历史段落均检查本次选择，各入口重验当前相应用途授权。发送需要model，用户读取与本地保存/发布需要local，发布再验独立写根；撤销model不自动撤销local。旧请求缺省字段不追加默认内容，不改变历史 P4/P5 请求与输入 hash。批注评论只作用户观点；高亮定位只有在已有锚点重验成功后显示页码。批注当前性指最后一次显式导入，不监控或擅自读取 Zotero 数据库。
10. 外部 Markdown 通过已有读取根及相对路径预览，用户确认准确 hash 后登记独立不可变版本；保留 `user_view` 或 `external_source` 归属，`source_verified=false`，不借用原 Wiki 证据、论文身份或写权限。新文件内容不自动产生新版本，追加版本需要明确基线；模型消费还须独立用途授权和逐版本选择。Lint 的文档范围目录包含草稿/失效文档，个人文档标题也受当前读取授权保护。
11. HTTP搜索/分页/准备/历史快照/回答/Wiki及外部文档响应属于local读取，即使请求purpose=model仍须另验local，不能借model权限返回已撤local的内容。内部模型读取能力保持独立。普通Query沿原include_personal与当前用途权限兼读已保存Wiki中的新typed依赖，不扩旧Query请求；P5有显式选择字段时仍严格检查已选根，不退回Query的广义个人范围。旧版本diff、P11基线及P09诊断中的间接个人资料也受相同边界保护。
12. Lint报告的只读状态观察不推进扫描。活动报告同步当前状态，完成/取消等终态不被迟到响应覆盖；重新打开未完成报告需显式继续。桌面单次推进100项，仍在现有1～100上限内，每调用完整验源；API默认25不变。unknown保留为info信息缺口，不推断矛盾/补条件，完成提示与科学语义正确性分开。原生反馈修复的实际结果见[扫描状态验证](../p5-scan-feedback-verification-20261105.md)。
13. 每个 Lint 问题同时返回程序生成的只读 `repair_plan`：状态、处理摘要、逐步方案和保护边界。按规则区分来源检查、证据/支撑重建、文档依赖更新、私人笔记只读快照与受管文件发布恢复；已消失的问题不提示重复修复，输入过期时先重新扫描。`SOURCE_UNCHECKED` 的方案是检查来源、记录可用性、重新运行 Lint；`CONDITION_UNKNOWN` 的方案是回查正文/表格/图注，有明确证据时才准备受控重建或新版本，不直接编辑旧条件；原文未说明时继续保留 `unknown`，不据此推断 `conflicting` 或补造条件。
14. `repair_plan` 仅在读取问题时派生，不持久化、不参与问题指纹，也不进入 P09/P10/P11 的冻结快照、模型输入或 hash。方案展示不调用模型或执行写入；步骤的 `requires_model=false/true/null` 分别表示此步骤不调用模型、需要另行授权的模型流程、由后续受控流程决定，缺省按未确定展示。后续动作仍须独立检查其协议、用途授权、来源、版本与预算；本次方案不授予模型或写入权限，不修改原文、EvidenceSpan、知识节点、历史 raw 或私人文件。

## 验证边界

离线协议、自动化规则、真实浏览器组件、冻结引擎、真实模型科学质量和用户原生反馈分别记录。未得到新的清楚预算前不调用真实 P09/P10/P11，也不复用已结束的 P4 请求授权。

个人笔记、批注评论和外部 Markdown 的合成数据协议/权限验证不替代真实 P09/P10/P11 的逐段科学验收。复杂表格、公式与无 OCR 限制延续。标准文件比对后原子替换并非与任意不合作编辑器之间的原子 CAS；断电耐久性、干净机及跨平台未由检查点测试证明。
