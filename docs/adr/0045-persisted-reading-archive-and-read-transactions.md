# ADR0045：本地阅读存档与独立只读事务

日期：2026-11-16（Asia/Shanghai）。状态：采用。

## 问题

用户打开论文精读时遇到 `DATABASE_BUSY`，怀疑每次都重新解析。现有 `lite_reading_documents` 已保存完整阅读视图，但读取仍重新组装并 flush；全文笔记读取也会经由过期检查走同一条路径。SQLite 普通 Session 首次查询使用 `BEGIN IMMEDIATE`，因此多个逻辑上的读取会竞争写锁。截图不足以确认当时具体哪个连接持锁，本轮不把提示解释为确定仍有后台任务。

## 决策

1. 保留现有数据库与 `reading-document-2` 语义版本，在投影 JSON 中增加完整来源/布局指纹与存档视图哈希。每次读取仍核验原始块、Span 原文/偏移/页码/坐标、章节与当前结构；命中后直接返回已保存视图，不重排、不合段、不 flush，不读取外部 PDF。
2. 拆分只读准备与乐观发布。首次打开或旧存档缺少校验字段时，从已存原文构建阅读视图；退出读快照后，使用独立短写事务尝试归档。仅此可选归档使用零等待写锁，遇到 BUSY/LOCKED 仍返回本次成功读取的内容，下次读取再尝试保存。其他数据库错误不伪装成功。
3. 发布前重验来源指纹及旧存档完整状态；若另一个请求已更新存档，跳过旧准备结果，防止回写覆盖新 scan、警告或整理时间。数据库仍 `lite0010`，无新迁移，不改写原始块、Span、历史模型结果或个人状态。
4. 显式“重新整理本地阅读版面”才重新扫描已登记、同 SHA 的 PDF。文件读取和解析在只读快照阶段进行；进入写事务后再次检查选定版本与 SHA，随后增量发布解析/章节/索引/存档。写入发布仍串行，读取可继续查看已提交版本。
5. 论文、任务、用量、模型配置及阅读相关纯 GET 统一使用受 `query_only` 保护的 `read_session`。模型生成、任务状态修改、个人状态保存、布局保存等仍使用正常写事务。笔记过期检查支持只读投影读取，不记录缓存命中或用量。
6. 界面提供“重新读取本地存档”，仅重新 GET 正文和已有笔记；与重新整理、模型生成分开。读取完成后显示内容就绪，有实际整理时间才展示。笔记读取失败不隐藏已成功读取的正文。
7. 注册静态关键词读取路由时优先于 `/qa/{qa_id}`，避免完整应用把 `qa/keywords` 当作问答 ID；纳入实际应用并发回归。

## 边界

存档不是完整 PDF 副本。Zotero 仍为原文来源；已保存文字可离线读取，重新扫描、图像原图和外部原文跳转仍需要原始文件。存档字段缺失或版面变化才本地重建；只有用户明确生成笔记才可能调用模型。章节识别、公式及 OCR 能力不由本次事务修复扩展。

持续写锁可能使首次归档暂缓，但不阻断本地读取。独占数据库维护、文件权限/磁盘故障或损坏仍可能令读取失败，不宣称所有 SQLite 错误均已消除。实际并发、重启、缓存及安装结果见 [验证报告](../reading-cache-verification-20261116.md)。
