# ADR 0007：空占位字段兼容与响应超时拆分

日期：2026-11-02（Asia/Shanghai）。状态：实施。继承 [ADR 0006](0006-graph-stability-and-local-reference-repair.md)，Schema head 0009，无迁移。

## 实际问题

用户本轮两个任务分别保留 1/4 和 6/16 个成功批次。前者返回合法 JSON，但 5 个 Claim 多出 `findings_placeholder:null`，被 extra_forbidden 拒绝；后者第 7 批 75 条证据、8371 个原文字符，三次约 90 秒后超时。此前成功批次也有超时后同输入重发；原日志无连接/响应阶段，因此不能断言网络故障或供应商内部排队。

运行旧 P02 含参考规范与后置适配，存在不够直接的字段指引；JSON object 模式只约束 JSON 可解析性，不等于服务端领域 Schema。严格 Schema 保留，不能简单允许所有额外字段。超时不能靠无限增加时限或原样重发解决。

## 决定

1. 入口只移除 `items[*]` 中 kind=Claim 的 `claim_detail.findings_placeholder` 且值严格为 null 的已知空标记。空列表、空对象、非空值、其他未知字段和其他路径仍拒绝。完整响应保留在原 ModelRun.raw_output，parameters.normalization 记录规则、路径及原校验错误。没有科学值被丢弃或补造，不额外调用模型。
2. 旧 validation_failed 响应仅在上述确定转换后合法，或只剩可修复的局部引用错误时可复用。后续仍走完整 Schema、来源、证据和 KnowledgeStore；非法来源不能因规范化而被接受。成功后清理当前运行错误状态，审计信息保留。
3. 新任务使用独立版本文件 `P02_unified_section_extract_v3_2.md`，精简重复/冲突指引，列明 ClaimDetail 属性，禁止占位字段，缺失列表用 [] 或省略。DTO unified-v3.1 保持不变；旧文件不修改。
4. unified_plan 持久化 prompt_name。已有无此字段的计划仍映射旧 P02 并验证原签名；新任务默认新版。原 48 批等无计划旧任务继续原规则。不可任意指定文件路径或跨模型续跑。
5. 新计划以 8000 原文字符、64 条完整证据为目标上限，已知模型较小上限仍可缩小。候选数量提示按原文字数设为 4–16，新拆子批持久化该提示；已存在的子批保留旧输入身份。单条证据不裁剪，旧计划不重排。表格行缺列头时不得猜测完整实验，使用 warnings 标记歧义。
6. Provider 记录输入字节/证据数、发送结束/响应头耗时、响应字节、总耗时及 timeout_phase，错误区分连接/发送/等待响应/读响应；不记录凭据或响应正文到错误消息。
7. 统一抽取在明确等待/读取响应或总时限超时后，不原样连续重发；未拆根批可按累计原文长度二分一次，保持完整证据。子批再次超时明确停下，避免网络故障导致无限拆分。连接/写入/连接池、429/5xx 等仍使用有界传输重试；输出/上下文截断维持最多三层拆分。
8. 对旧任务已经记录三次 timeout、同证据集的未完成根批，用户继续时直接建立一次拆分账本，避免再发同一大请求。成功批次与成功子批按原操作键跳过；拆分总数可能增加。旧日志没有阶段时将其作为一次保守恢复机会，不能冒充已识别网络原因。

## 费用与兼容边界

保持配置的 90 秒（可配置 5–180 秒）请求限制与原任务层收尾时限，不提高超时上限。超时请求可能已在远端执行，未返回用量不能当作零。一次根批二分不等于所有真实论文都不会超时；服务不可用时应停止并保留当前进度。

不修改正式数据库作实验；真实响应复核在一致性副本上，原知识/原始输出逐行比对。原 PDF/Zotero/笔记只读。测试与实际结果见[本轮验收](../extraction-reliability-verification-20261102.md)。
