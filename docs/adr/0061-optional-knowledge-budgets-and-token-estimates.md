# ADR0061：知识库可选预算与一致的 Token 容量估算

日期：2026-11-20（Asia/Shanghai）

状态：已实施；验证结果见[本轮报告](../knowledge-budget-verification-20261120.md)。

## 背景

用户要求知识库单次输入、单次输出及每次分析请求数可选择“无上限”，并修复 `KNOWLEDGE_INPUT_BUDGET_EXCEEDED`。只读检查确认报错任务以默认 48,000 输入预算拦截，`request_sent=false`，没有原始响应。该材料完整传输结构的本机估算约 79,268 Token，因此调高预算或取消软件上限是必要操作；该数不是供应商 tokenizer 实测或收费量。

同时发现 K2/K3 与通用文字 Provider 在上下文容量检查中混用了 UTF-8 字节数和 Token 数；K3 还直接用软件输出预算作固定上下文预留。无限选项若只改界面会导致 null 算术、错误分批或取消端点容量保护。

## 决策

1. `LibrarySettings.max_input_tokens`、`max_output_tokens`、`max_requests_per_run` 使用 `int | None`。JSON `null` 表示不加这一项软件限制。缺字段沿用原默认值 48,000 / 6,000 / 2；有限值校验范围保持。JSON 设置及历史策略无需迁移，数据库 head 仍为 `lite0018`。
2. 当前设置与冻结策略按 `null=∞` 取交集。已排队或自动运行不会因为后来放宽设置而扩大授权；显式继续失败任务才以新设置创建后继。原失败、冻结策略、原始响应及请求账本保留。输入预算预检失败不占已发送模型槽，不自动发请求。
3. `token_estimates.estimate_tokens` 统一文字估算：ASCII 约三字符一个 Token、非 ASCII 每字符两个 Token，向上取整。K2/K3 包含完整材料、指令和 Schema；ConfiguredProvider 按实际消息结构再验。记录估算方法与 `input_token_estimate`，`input_bytes` 只代表传输大小。该算法用于本机规划，不宣称等价模型 tokenizer。
4. 无输入软件上限仍检查已知上下文，完整知识对象/比较材料不裁剪。无输出软件上限不额外设置任务 cap，已知端点输出限额及输入后的上下文余量继续约束请求；未知端点输出时沿用供应商默认，不猜测无限容量。知识任务至少预留 2,048 输出 Token 与 512 上下文余量。
5. 无每次分析请求数上限只取消旧单次 cap，候选数、累计请求预算、持久预占/发送账本、同一输入的显式重试上限均保持。发送前再次检查收紧预算及来源，不以“无上限”免除联网授权或来源校验。
6. 三项界面独立勾选“无上限”，保存 null；取消恢复最近有限值，持久 null 重新打开时使用原有限默认值作为恢复值。错误提示引导用户调整设置并显式继续；保存设置不重发失败任务。任务记录不会把知识模型任务标成“重试本地处理”。

## 模型配置边界

DeepSeek V4.1 Flash 必须按接入平台和套餐查证。当前用户使用火山方舟 Agent Plan 的 `/api/plan/v3`，与 Coding Plan 的 `/api/coding/v3`、DeepSeek 官方 `deepseek-flash` 及现有 Tencent 适配器分开。此轮提供官方来源和配置建议，不自动修改用户模型配置或增加未经验证的跨平台别名适配。详见[推荐配置](../deepseek-v41-flash-recommendations-20261120.md)。

## 后果与限制

长文可由用户明确取消软件预算后重试；若真实端点容量不足仍拒绝或由服务返回容量错误，不自动拆论文、降低质量或再次收费。估算对特殊字符、公式、编码文本可能偏差；真实用量以供应商实际 usage 为准。此次没有付费模型验收，也不把合成 Provider 回归当作科学质量或真实平台 SLA。
