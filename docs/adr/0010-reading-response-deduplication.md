# ADR 0010：阅读抽取的精确重复去重与失败响应续用

- 日期：2026-11-02（Asia/Shanghai）
- 状态：已实施，真实失败响应在隔离副本回放通过；全文和用户安装反馈仍待验收
- 范围：R5 可靠性，承接 [ADR 0009](0009-reading-pipeline-implementation.md)。此 ADR 编号不代表数据库迁移；Alembic head 仍为 0010。

## 问题

真实 P02_reading_extract 输出 28 条候选，其中 8 条重复使用 local_ref 且完整 JSON 对象与前项一致。原契约正确要求编号唯一，但整个响应被拒绝，界面只显示 batch(value_error)。旧失败缓存只识别 unified-v3 的兼容规则，直接重试可能再次付费取得同一批内容。

## 决策

1. 在领域契约之外增加确定性响应适配：先验证完整包络、全部候选/关联字段、列表长度及所有证据白名单，再处理重复项。额外字段、越界证据和超长列表不能通过去重或隔离逃过检查。
2. 只合并同一 local_ref、原始 JSON 对象完全相同的候选。JSON 对象字段顺序无关；不依据语义相似度、Pydantic 默认值或类型转换合并。不同编号的语义去重仍由后续机制处理。
3. 相同编号但不同内容直接拒绝，错误包含冲突项序号，不回显私人内容。不重命名编号、不猜关系目标，也不调用模型修复这种歧义。
4. 原始 ModelRun.raw_output 不变，参数中记录 reading_normalization、规则版本 exact-local-ref-duplicate-v1、保留/移除的零基索引。关系端点不变，去重不表示知识缺失或覆盖不足。
5. 对完全匹配任务输入、Prompt、Schema、模型和参数的失败响应，重新严格校验来源版本、批次和证据白名单后允许复用。随后仍经 KnowledgeStore 校验真实 quote/offset/源版本、原子写入、幂等与事件记录。成功批次不重调；不能继续时保留旧结果。
6. 不改变运行 Prompt、JSON Schema、分块计划或签名。已有 reading-extraction-1.0 任务可继续，数据库无迁移。旧 unified 的空占位和端点修复规则不扩大到阅读契约。
7. 界面将子批状态改为“已保存（超时拆分后）”，任务级仍显示已保存批次总数和当前阶段。只有完整流程成功才显示任务完成。模型记录显示精确去重说明，常见引用校验错误给出安全中文原因。

## 关于全文一次提取

一次选择/上传/读取 PDF、一次模型调用、一次完成结构化建图是不同边界。当前软件已经一次点击自动执行抽取、整合、选择，但 P02 使用 6000 字符/48 证据的保守分组。短文本可单批，长论文仍多批；这是当前工程策略，不能说模型必然只能读取这么少。

后续 R5 可评估预算自适应：同时计入全文/Schema/证据输入、预期候选输出和推理用量，已知能力且可容纳的小论文选单批，长论文采用全文结构规划与定向证据抽取。预算未知时不猜供应商上限，不把最大上下文当最大输出，不在失败后无限重发。该策略尚未实现；不得据此改变正在进行的任务或宣称单次全文已验证。

## 验证

见[本轮报告](../reading-response-verification-20261102.md)。包含严格重复边界、冲突和私人文本脱敏、来源及列表上限、旧失败缓存零调用恢复、成功批次不重跑、原输出保留、真实响应隔离回放。离线回放不替代新模型全文验收。
