# 00 — 架构决议与边界（ADR-RG-003）

## 1. 这次修改的主要原因

此前Phase 2/3使用者面临三个阻力：LLM结构化抽取后仍需逐项审核才能生成图谱；大量解析块暴露在页面中，产品像PDF解析器；实体/证据/条件直接显示为大量节点，网络不易探索。目标改为**默认自动建图，简洁展示，保留证据追踪**。

## 2. 本次明确决定

1. **自动入图、不以人工审核作为可用前置条件。** 程序进行Schema/引用/锚点/重复检查；通过的候选立即以明确状态进入可用图谱。用户可主动纠错；高风险覆盖已有人工修订知识仍需受控确认。
2. **领域模型与图谱视图分离。** 不删除Paper/Claim/Evidence/Condition/Finding/Experiment/RelationAssertion等完整数据；前端GraphProjection只返回短标签、类别、ID、状态和必要视觉属性，详情另取。
3. **默认只显示五类节点**：Paper、Concept、Method、Claim、ResearchQuestion。条件、实验、结果、证据作为结构化详情并保留持久化引用；高级模式可临时展开细节。
4. **低操作成本。** Zotero选Collection与PDF附件后可直接“开始建图”，无需重复导入/逐条审批。允许直接PDF文件模式作为备用。
5. **抽取任务合并。** 同一章节/上下文块一次获取Concept、Method、Claim、ResearchQuestion和相关Experiment/Finding/Condition；仅异常补偿、跨块融合或双语标签不合规时增量调用模型。
6. **允许批次增量可见**。已完成批次提交事务后前端更新局部图；失败批次保留，继续时不能重复扣费/重复节点。
7. **中文优先展示，英文保留**。自动中文译名仅用于显示和辅助理解，不作为原始证据；可选择中文/英文/双语标签。
8. **Zotero保留原始PDF与阅读职能**。ResearchGraph只读附件并生成必要解析缓存和锚点；不默认复制PDF至应用库，不展示全文阅读器。
9. **跨论文关系分级呈现**。来源支持的结构边可以自动展示；LLM推断边显示“AI候选”虚线与来源，不能自动认定科学证明；`NO_DECISION`不创建科学关系边。
10. **保持统一Knowledge Engine**。Ingest/Query/Lint/Wiki共用知识对象与写入机制；Query默认只读，Lint审计图谱；Wiki是派生综合表达，不是另一个科学事实数据库。

## 3. v2 → v3关键差异

| 范围 | v2设计重点 | v3实施决策 |
|---|---|---|
| 审核 | 人工审核作为主工作台的重要环节 | **自动可用**，人工审核为可选异常/纠错 |
| 图谱 | 强调完整实体关系表达 | **默认简洁投影**，详细属性按需加载 |
| 抽取 | 多抽取器分阶段，存在较多调用 | 合并章节级结构化抽取；严格证据核验仍保留 |
| 交互 | 论文解析内容/候选列表占较多空间 | 图谱为主；论文内容用于证据弹出/跳转Zotero |
| 构建时间 | 等完成/审核后统一建图 | 单批提交即可更新可见子图；后台继续运行 |
| 双语 | 提供翻译字段 | 中文短标签为首要视觉属性，英文及原文可回查 |
| 可持续性 | 新文献推动Graph和Wiki更新 | 依赖图谱持续更新；Query/Lint沿用统一知识生命周期 |

## 4. 不做的事情

- 不重新造Zotero阅读器或导入后长期复制PDF；不让LLM生成虚构页码、Quote、附件路径和数据库ID。
- 不把`source_anchored`解释为结论科学上已证明；不因“已自动展示”而自动把用户确认的结论覆盖。
- 不为所有知识创建可见的Condition/Evidence/Metric细节点；不要求用户每条勾选。
- 不用GraphRAG代替完整证据核验；不在本轮推翻当前P2/P3数据库重建工程。
- 不把LLM直接接收PDF视为可靠的引用锚定解决方案；可以试验直传模型，但必须同时维护原文解析/坐标索引、引用回查与成本对比。

## 5. 有争议时的优先级

**来源原文与用户数据完整性 > 可重复性/安全 > 自动可用 > 简短图谱体验 > 额外UI装饰。**
