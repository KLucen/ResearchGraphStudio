# 06 — 开发计划与现有P2/P3工程兼容迁移

> 本文是**在既有Phase 2及Phase 3工程基础上的v3设计迭代计划**，不是重新执行Phase 0。真实完成情况由Codex检查仓库代码和测试决定，不能仅依赖对话中的阶段说法。

## 1. 技术栈（沿用现有选型）

| 层 | 推荐框架 | 约束 |
|---|---|---|
| 桌面 | Tauri 2 | Windows安装包、Sidecar无终端弹窗、权限控制 |
| 前端 | React + TypeScript + Vite | 现有UI组件/路由复用；集中布局状态 |
| 图谱 | @xyflow/react + 有界力模拟 | 实时力导向、双击固定、局部加载；不强制替换已有组件 |
| 服务 | Python 3.11+ + FastAPI + Pydantic v2 | 结构化契约、任务API、来源验证 |
| 数据库 | SQLite + Alembic/现有迁移工具 + FTS5 | Evidence、知识、历史、布局持久化 |
| PDF | PyMuPDF；GROBID可选 | 原文偏移与坐标；不能只靠LLM直传PDF |
| LLM | 可配置OpenAI/OpenAI-compatible/local | 密钥安全、结构化降级、费用预算 |
| 集成 | Zotero Local API | 只读Collection/item/attachment，不复制正式PDF |
| Wiki | Markdown/Obsidian | 后续在授权目录输出衍生文档 |
| 测试 | pytest + 前端测试工具 + Mock/集成验收 | 每阶段跑回归，禁止以Mock冒充真实API验证 |

## 2. 施工方法

1. **审计现有P2/P3实现**：当前Schema/DB、抽取流程、审核UI、Graph API、Provider和任务系统。
2. **形成映射表**：既有Paper/Claim/Evidence IDs与v3域模型/投影属性对应；保留现有用户数据。
3. **先建GraphProjection、双语display与状态兼容**，不先迁移所有领域表。
4. **解除人工审核前置**：实现验证成功自动发布和图谱增量事件；人工Review API保留为可选纠错。
5. **合并章节级抽取**：P02统一Prompt，验证和历史数据按增量方式接入。
6. **UI图谱优化**：拖动、固定、详情、中英和局部图；移除大段解析块默认展示。
7. **强化批次任务稳定性**：超时分类、断点恢复、幂等和费用可见。
8. **用真实论文与真实LLM检查端到端行为**，再完成发布和文档。

## 3. 本轮增量任务包（优先级顺序）

### M0 — 现有工程审核与安全备份

- 验证已完成P2/P3实际功能；检查未提交更改、数据库备份/迁移路径、旧任务结果与API Key管理。
- 输出`docs/migration/v2_to_v3_assessment.md`，记录需要改动的实体、字段和前端节点接口。
- 不能清空DB、覆盖Zotero附件或用户手工笔记。

**完成条件**：已有P2/3导入、抽取、查询和图谱接口回归基线可运行；迁移策略形成。

### M1 — Graph Projection与自动图谱显示（最高优先级）

- 增加`GraphProjectionService`和图谱API；默认只映射5类节点；源关系与AI候选边线型区分。
- 证据有效的知识通过KnowledgeStore自动入图；不需人工审阅才能显示；旧Review工作流保留为可选。
- 实现局部图谱分页/限深、点击`detail_ref`、KnowledgeRevision事件。

**完成条件**：使用现有已抽取数据，不重跑LLM即可显示可操作图谱；空Review Queue不会阻止展示。

### M2 — Node Inspector与Obsidian风格拖动布局

- Graph Explorer增加搜索、筛选、邻居高亮、平移缩放、实时力导向、双击固定与保存布局。
- 详情面板显示中文短名、完整英文/中文描述、Method/Claim/实验/证据和Zotero入口。
- 侧边栏折叠时重新计算画布；修正旧页面大段PDF解析文本作为主内容的问题。

**完成条件**：移动节点、刷新/重启位置一致；Claim可追溯Evidence；手机尺寸不是首发目标，但桌面窗口缩放正常。

### M3 — 单批多类型LLM抽取与双语标签

- 接入P02统一提取（Concept/Method/Claim/ResearchQuestion及嵌套实验/结果/条件），同时生成中文/英文短标签。
- 旧分阶段抽取器仅用于历史任务兼容和显式测试，正常界面移除旧基线开关与 Mock；使用全局真实 Extraction 模型。
- 实体融合P03在图谱建好后按需执行，P04仅修复翻译字段；不阻塞已有合法英文节点。

**完成条件**：相同论文在统一流程下能够自动建图、双语完整、来源锚点可查，模型调用次数/时长/费用可记录并与旧流程比较。

### M4 — 增量任务与错误恢复

- 每批在独立事务提交后GraphRevision增长；前端及时显示已构建部分。
- 添加任务状态、重试退避、取消后恢复、重复批次幂等、费用/Token记录（Provider提供时）。
- 真实API故障注入（超时/429/无效JSON/缺Evidence）；不能因一批失败导致已保存批次丢失。

**完成条件**：7批中途失败后继续能够跳过已提交批次，不重复入图，失败原因可追查。

### M5 — 条件化关系与双语图谱整合

- 复用现有P3比较和RelationAssertion；`NO_DECISION`不形成科学边，候选关系虚线。
- 中英显示与正式源证据分离；边详情显示可比性和模型来源，支持用户可选纠错。

**完成条件**：两篇研究条件不一致的论文不会被默认画成已证实矛盾；Claim Comparator可正常打开完整条件和证据。

### M6 — 验收、发布与架构基线更新

- 运行旧P0–P3回归 + 新v3契约/交互/断点任务测试；完成有权限的真实API小样本验证。
- 更新`AGENTS.md`、阶段进度、API、Schema/Prompt版本、迁移ADR及用户手册。
- 保证Windows正式版不弹出命令行终端；GitHub提交前执行Gitleaks等密钥/私人文件扫描。

**完成条件**：安装与真实论文验收有记录，无法执行的验证要明确标注为“未测”。

## 4. 后续Phase兼容路线

| 阶段 | 开发内容 | 与v3自动建图的接口 |
|---|---|---|
| P4 Query | Graph+Evidence+Notes混合检索，回答分层引用、用户保存知识 | 查询完整版领域Schema，不能只检索5类视觉投影字段 |

## 5. 验收矩阵

| 维度 | 必需用例 |
|---|---|
| 自动建图 | 无人工审核直接显示5类节点，Evidence缺失分流 |
| 数据兼容 | 老项目、已审核记录、旧证据ID和图谱关系不丢失 |
| 双语 | 短中文标签、英文回退、完整双语详情、否定/数字一致 |
| UI图谱 | 拖动、固定、搜索、缩放、局部加载、重启布局保留 |
| 断点续跑 | 7批中第2批超时，已提交批次保留，重试不重复入图 |
| 关系判断 | 条件不可比时NO_DECISION，候选边和已确认边不同 |
| Zotero | 选择Collection/附件后直接解析，不重复存储PDF |
| 安全 | API Key无明文、源PDF/数据库不提交GitHub、日志脱敏 |
| 跨阶段 | P4 Query / P5 Lint仍可访问完整Evidence/Condition/RelationAssertion |
