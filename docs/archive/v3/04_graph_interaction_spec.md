# 04 — Graph Explorer交互规格（Obsidian风格，不复制其数据模型）

## 1. 交互目标与信息密度

目标是“看关系、点节点、查详情”，而不是在画布上读完论文。默认五类核心节点，显示4–18汉字左右的中文简短标签，英文/完整原文/条件/结果隐藏在详情面板。初次进入项目展示上次图谱、最近更新与当前任务进度，不弹出每节点审核向导。

### 画面建议

```text
┌─ 可折叠导航 ─┬─────────────────────────────────────────┬──────────────────────┐
│ 项目          │ 搜索  [Paper][Concept][Method][Claim][Q]   │ 节点详情 / Claim      │
│ 文献来源      │                                         │ 中文短标题           │
│ 知识图谱  ★   │      ○ Paper ─── ○ Method               │ English name         │
│ 任务          │            ╲        ╲                  │ 中文摘要 / 原文主张   │
│              │             ○ Claim ─── ○ Concept       │ 条件 / Finding       │
│              │                     ╲                  │ 证据 / 打开Zotero    │
│ 设置（底部）  │                       ○ ResearchQuestion│ 相关节点 / 状态      │
└───────────────┴─────────────────────────────────────────┴──────────────────────┘
```

## 2. 节点交互

| 手势/操作 | 行为 | 持久化语义 |
|---|---|---|
| 鼠标拖动节点 | 实时力导向：被拖节点跟随指针，其余节点动态避让或跟随 | 更新`graph_layouts.x/y`，不增GraphRevision |
| 双击或固定按钮 | 固定/释放节点（pinned） | 保存布局偏好 |
| 单击节点 | 高亮本节点与一阶邻居，右栏加载详情 | 仅UI状态 |
| 详情中的“聚焦邻域”按钮 | 展开一至三度邻居 | 改变局部视图 |
| 点击边 | 打开关系说明、来源与推断状态 | 不修改知识 |
| 画布空白拖动 | 平移；滚轮缩放；按钮重置视图 | 可保存viewport |
| 搜索 | 匹配中英名称、作者、Paper ID、概念别名 | 对局部图谱过滤；可跨库查找 |
| 筛选 | Paper/Concept/Method/Claim/Question；仅来源锚定/含AI候选 | 仅显示层变化 |
| 悬停 | tooltip（英文名/完整短标题）和邻居提示 | 仅UI状态 |

## 3. 布局策略

- 首选复用当前`@xyflow/react`，与`d3-force`或现有布局模块结合实现初始力导向布局；不因这次迭代强制迁移Cytoscape.js。
- 节点位移与模拟产生的位置更新采用节流，控制React渲染频率；物理系统能稳定停止，不能一直漂浮抖动。
- 拖动只临时固定到指针；双击或详情按钮切换持久固定。提供重新布局，尊重已固定节点与相机位置。
- 使用小圆点及半透明低饱和连线；悬停高亮一阶邻居。局部模拟通过 requestAnimationFrame 更新，松手/冷却后保存，不能每帧写数据库；遵循减少动态效果偏好。
- 侧边栏折叠/详情侧栏展开后调用FitView或更新尺寸，避免画布错位、节点被裁剪。
- 可配置弱重力、排斥力、连线长度；超大图谱默认显示限深子图并支持按需加载，不能将全库上万节点一次发往客户端。
- 长标签使用折行/省略+tooltip；颜色之外还用线型/图标表明关系状态，兼顾可访问性。

## 4. 节点详情字段与分层

### Paper

标题、作者、年份、Zotero item、可用PDF附件、DocumentVersion、抽取进度、概念/方法/Claim数量、“在Zotero打开”。不用默认显示解析全文。

### Concept

规范中文名、英文名、别名、简短双语定义、出现的论文与方法、置信及校验状态、可定位的来源证据。

### Method

中文短名与英文名、机制解释、实现/适用范围（适用时）、相关Experiment/Finding、相应Paper及Evidence；若作者提出多种变体，允许展开。

### Claim

中文短标题、完整`statement_en`与`statement_zh`、作者主张归属（本文作者/转述他人）、语气强度、Condition（known/unknown/not_applicable/conflicting）、Finding、关联Method和Paper、原文EvidenceSpan、翻译状态及推理关系。

### ResearchQuestion

问题简短中文标题、完整中英文问题、由谁提出、相关Claim/Method、是否有已知证据及相关开放问题。

### RelationAssertion详情

关系双方与源Paper、条件对比表、判断理由（中英文可选）、引用证据、AI/人类状态、ModelRun版本及“纠错”操作。`NO_DECISION`不显示为科学关系边，可在比较历史中查看。

## 5. 状态视觉语言

| 状态 | 画面 | 语义 |
|---|---|---|
| 原文锚定知识 | 普通实线源关系，可见简洁节点 | 抽取来自论文，非科学真理证明 |
| AI推理候选关系 | 虚线，灰/琥珀标识 `AI候选` | 只是一种待验证判断 |
| 用户已确认推理 | 实线+`已确认解释`标识 | 用户审阅过，仍不等于科学已证明 |
| 证据缺失 | 默认藏于诊断筛选，或带警示标识 | 不能通过直接显示而假装有证据 |
| 已废弃旧知识 | 默认隐藏，历史视图可查看 | 保留演化追踪 |

## 6. 任务进行时的反馈

图谱页顶部或任务抽屉显示：当前论文、完成/总批次、有效节点、失败批次、模型、费用（有数据时）、取消/继续。每批提交后局部图实时增加；不强制弹出覆盖全屏的“正在审核”对话框。完成后可选FitView与局部重排，尊重用户已固定节点位置。

## 7. 响应式与键盘访问

最小主工作区宽度应覆盖常见笔记本屏幕，狭窄窗口中右侧详情变为抽屉；折叠导航可保留图标+tooltip。键盘Tab可聚焦搜索、筛选、节点列表和操作；Enter打开详情，Esc关闭。不要依赖悬停才能访问重要内容。

## 8. 验收场景

运行实现补充（2026-11-02）：受控点节点携带稳定 width/height/measured，避免每次 hover 或模拟更新清空测量导致隐藏；边文字不能截获节点指针，非有限位置拒绝进入布局。自动化必须覆盖真实 React Flow 渲染下的悬停与连续拖动，不能只 mock 组件回调。

1. 导入真实Zotero论文后，无逐条审核即可看到Paper/Concept/Method/Claim/Question节点。
2. 自由拖动、平移缩放、固定节点；切换页及重启后布局一致。
3. 点击Claim查看中英双语、具体条件、Finding、证据页号并可打开Zotero。
4. 选择“只看论文锚定”会隐藏AI候选推断关系；重新打开则虚线出现。
5. 当节点超过阈值时仍能显示局部图而不明显卡顿；局部图过滤不会删掉领域数据。
