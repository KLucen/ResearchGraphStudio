# Lite 模型配置

2026-11-20 知识库模型：设置中新增独立`knowledge_extract`（论文知识建模）与`knowledge_connect`（论文联系分析）用途，沿用已配置的真实Provider/Profile。旧概览可在论文概览或知识库中零模型收藏；“生成带来源知识”将所选本地解析或模型解析材料发送给建模模型，不重新读取或上传PDF。新`paper-knowledge-1`一次生成卡片与带引文知识图，旧概览v1、精读和译文合同保持可读；不把旧无出处图自动变成带来源知识。

知识库“自动分析设置”中的两项开关分别为“新解析完成后自动构建论文知识（调用模型）”“新知识版本入库后自动分析联系”，必须明确勾选范围/预算内网络授权。默认均关闭、同项目比较；可改为指定专题或全库候选。默认候选8篇、每次关联最多2请求、输入48000/输出6000 Token预算、累计20请求；这些是可调软件策略，不是模型容量或价格承诺。累计额度同时包含建模和关联已发槽位及活动预留，清理内容不会返还已消费额度；费用未知继续显示未知。策略保存仅对后续事件生效，不为既有全库批量补跑。

知识建模当前按完整已解析材料一次提交，容量预检失败整体停止，零发送、不裁剪且不自动拆批。同一解析输入最多2次显式发送，持久发送槽位在网络前记录；固定坏响应不自动格式修复或收费重试，合法已收到raw可显式本机重验恢复。联系分析按冻结候选版本及双侧依据分组，成功版本对检查点会复用；更换关联配置可仍零调用复用已完成版本对，只有显式重新分析才绕过此复用且受原预算约束。失败/中断的继续入口也需用户明确操作。实际边界和验证见[ADR0060](adr/0060-durable-research-knowledge-library.md)及[本轮报告](knowledge-library-verification-20261120.md)。真实Provider科学质量、复杂公式/表格语义仍未验收。

2026-11-19 后续修复：模型材料精读新任务冻结合同v4，继续使用v3固定编号槽位，同时明确高亮类型及THESIS含义；译文合同和旧v1/v2/v3任务不变。精确的CLAIM可在用户明确操作后本机映射为THESIS；引文不匹配项被隔离，输出标为部分可用。此恢复不调用模型、不收费、不覆盖失败状态/raw；其他格式、来源和槽位错误拒绝恢复。新表记录恢复结果和来源版本，head为`lite0015`。长文本等待时限及传输/空响应/截断分类沿用；重新生成仍需明确操作且可能收费。详见[ADR0057](adr/0057-reading-output-and-workspace-recovery.md)和[本轮验证](workspace-fixes-verification-20261119.md)。

2026-11-19：模型提取稿现与本地材料共用概览卡片/图谱和全文精读组件。导入的概览、精读默认不选，页面显示当次保存选择；现有材料可显式补生成，精读1次请求，选择译文另1次，也可只补译文。格式失败后有可恢复本机响应时，可单独确认一次文本格式修复，不再次上传PDF；修复失败不能链式继续修复。没有raw、来源变化、请求失败及数据库错误不开放该动作。该轮 head 为 `lite0015`，新增表升级前自动备份，详见[ADR0056](adr/0056-unified-reading-from-parser-sources.md)与[本轮验证](unified-reading-verification-20261119.md)。

更新：2026-11-20（Asia/Shanghai）。既有本地 PDF 解析和阅读仍不调用模型；用户主动选择模型优先导入并勾选联网授权后，才会将 PDF 发送给解析模型。概览、全文精读和逐段翻译是解析后的独立可选任务；用户可以只保存章节解析结果。模型还会在用户主动生成 PaperCard + LightGraph、全文精读、证据问答及英文关键词辅助时使用。小节导读和独立理解状态入口已移除；章节已读标记与继续阅读是本地操作。

模型配置位于“设置与诊断”的“模型”板块。页面按提供商卡片展示连接，添加时可以选择 DeepSeek、OpenAI、OpenRouter、SiliconFlow、智谱 AI、通义千问和本机 Ollama 等兼容预设，也可以打开“自定义模型 API”填写 Provider ID、显示名称、Base URL、协议、API Key 和多个模型。当前运行引擎只实现 OpenAI Chat Completions 兼容路径；原生 Anthropic 等协议不在界面中宣称已支持。

一个提供商下可以维护多个模型 ID/显示名称，保存后作为现有 model profile 供论文概览、章节精读和论文问答分别选择。模型配置请求不会重复提交 Base URL 或 API Key。Provider ID 目前只用于本地界面标识，未进入数据库 Schema；若需要跨设备同步，后续再增加字段和迁移。API Key 只写入操作系统凭据存储，数据库保存随机引用。连接测试使用固定非论文文本，不代表科学质量验收。

模型解析要求模型与端点明确支持所选输入路线：PDF/文档文件输入配合 chat_file，或图片输入与多模态能力配合 chat_images。普通文本模型不会收到 PDF 或页面图片，也不会静默回退到本地解析；能力不足时导入项会显示失败或暂停。联网授权默认关闭。解析结果先保存章节、正文、公式和表格，再只为用户选择的项目创建概览、精读和翻译任务；翻译仅在全文精读下可选。详见 [ADR0047](adr/0047-import-time-post-processing-plan.md) 与 [ADR0051](adr/0051-document-timeouts-and-visual-pdf-input.md)。

2026-11-18 双解析更新：导入默认“本地解析（不调用模型）”，自动生成本地正文、章节和检索库。选择“模型解析 PDF”后才显示生成选项及 PDF 发送授权。勾选联网只表示允许发送，不能证明模型可以读取文件。

2026-11-18 超时修复：模型编辑中新增“文档等待超时”和“文档解析总时限”，默认分别600秒和1800秒，均针对单次HTTP请求，文字任务的原超时不变；分批后不是整篇任务总用时上限。批次准备也有默认1800秒的可配置deadline及逐页取消检查，单次原生页面渲染不能中途打断。火山/腾讯套餐地址可显示“应用推荐解析配置”，仅在模型确实支持视觉时选择页面图片，600/1800秒和none推理仍需端点支持，不因按钮存在而宣称能力通过。保存后在论文页点击“使用模型重新解析”，旧任务重试仍是旧快照；推荐为解析新建独立模型配置，避免改变其他新任务的推理强度。见 [ADR0051](adr/0051-document-timeouts-and-visual-pdf-input.md)。

2026-11-18 分页更新：新模型任务默认每批最多5页（可选2–8页，含相邻前1页共享），顺序发送，已知模型容量或图片上限只会缩小批次。核心页按原始页码保存，成功批次立即写入检查点，继续时不重新发送已成功批次。核心每页必须有来源片段或显式unavailable_pages警告，不以结构覆盖宣称识别完整。原始PDF软件上限50MiB/2048页；每个图片请求仍受128页、单页800万/总1.28亿像素与32MiB图片资源上限约束。容量无法容纳最小范围则停止，不截页或静默降级。这些不是供应商容量承诺。见 [ADR0052](adr/0052-resumable-document-batches.md)。

导入计划中“允许按需调用模型检查相邻批次的截断与续接”默认开启：仅有末首片段续接信号时发送相邻原始2页和两个片段，每边界最多1次，模型只决定merge/separate/uncertain。程序确定性拼接，简单同列表格的重复表头需精确匹配；复杂表格和不确定续接保留原片段与needs_review，不保证全文无缝。

“允许契约校验失败时修复本批格式”默认关闭，需要单独勾选；每个失败抽取批次最多额外1次API请求，发送该批响应/契约/脱敏错误，不重传PDF。再次校验和文字/页码/归属/顺序保护通过才保存，无法确认仅格式变化时拒绝，不用于科学校对。自lite0014起，失败原始响应保存在本机私有表以支持事后显式一次修复，不进入任务日志或普通API诊断；旧版本未保留的失败响应不能补造。若最终为B批，初始预算是B次抽取＋授权边界最多B−1次＋授权修复最多B次；概览、精读和翻译另计。改变相关选项后需重新勾选联网授权。

中断或发送结果不确定时不自动重发，用户明确继续才授权未完成范围，可能再次收费；每批最多3次显式执行，继续会扩展显示的请求预算，格式修复仍最多1次。检查点绑定会话、任务、冻结模型/协议、实际页范围和stat元数据源版本，不把SHA-256作为前置，也不宣称源文件等字节。未显式开批次的旧任务继续旧整篇路径。实现与专项证据见[本轮验证](document-batches-verification-20261118.md)。

模型解析配置步骤：进入“设置与诊断 → 模型 → 提供商编辑”，在相应模型下设置输入能力与传输方式。支持文件的模型可选 PDF 与 Chat Completions 文件内容（chat_file）；支持图片的视觉模型可选图片输入、多模态能力和“PDF 页面转图片”（chat_images）。保存后在“论文解析模型”选择该模型。文本连接成功不能验证文件或图片能力。仅支持文本的模型可继续用于概览/精读/问答，论文使用本地解析。修改能力或更换模型后，在论文页点击“使用模型重新解析”，勾选本次授权并确认；旧任务的“重试”沿用原冻结配置。已有论文也可点击“本地解析 / 重试”，无需重复导入。详见 [ADR0050](adr/0050-explicit-local-and-model-parsing.md)。

2026-11-18边界400修复：正文已校验而边界失败时，应先更新修复版；同样请求反复继续不会改变错误参数。已确认旧JSON提示缺陷的边界可在修复后显式继续一次，不重新发送已成功正文，即使旧边界已尝试3次也可提供受控恢复；修复请求发送后不再享受该兼容例外。无需为本故障更换模型或重新导入，详见 [ADR0053](adr/0053-boundary-json-compatibility-recovery.md)。

2026-11-19发布外键修复：正文和边界全部通过后出现 `SQLITE_CONSTRAINT_FOREIGNKEY (787)` 时，问题可能位于本地章节发布及概览任务关联顺序，已在新版本修正。原任务可在条件匹配时点击“仅重新发布章节（不重发批次）”，不重新上传PDF或请求解析批次，不需更换模型。旧版本已用完2次仅发布恢复的明确787失败任务有一次修复版兼容恢复；原次数保留，失败后不无限继续。文件版本或检查点变化会直接停止，不回落模型请求。原计划中的概览/精读可能在发布后单独产生模型费用。见 [ADR0055](adr/0055-document-postprocess-foreign-key-order.md)。

每次主动调用都记录 Provider、模型、Prompt/Schema 版本、输入/输出/总 Token、调用次数、重试次数、缓存命中和费用状态。供应商没有返回 usage 或价格配置时保留 `unknown`，不会把缺失值写成零。旧本地解析工作流的缓存按论文、PDF 哈希、输入哈希、Schema、Prompt、Provider 和模型绑定；模型优先导入使用来源快照、导入会话、解析运行及模型快照关联，不要求 SHA-256 作为发送前置或缓存命中条件。

LightGraph 使用补充规范中的 `PAPER_OVERVIEW_WITH_LIGHT_GRAPH_V1`，PaperCard 与概念图只发起一次联合请求。模型不得生成正式 ID、文件路径、数据库语句、Evidence 节点或段落证据引用；本地程序负责 Schema 校验、稳定 ID、缓存和布局保存。

全文精读与理解检查复用全局阅读模型配置及 Provider。A04 对整篇可读正文一次生成常驻译文和中文批注，不分析折叠图表材料，不追加校对或图谱抽取。按实际 Provider 的有效上下文和输出限制预检，容量不足零调用提示；不静默截断、不自动拆批。容量未声明时明确警告估算不能保证容纳。旧 A02 结果保留，A03 仅主动复述时调用。旧 A01/A02/A03 的接口和历史记录兼容保留，正常精读入口直接进入全文。大章节状态仅更新本地进度，保留旧自评和问题，不产生请求。费用和译文质量按真实返回记录，不从估算或合成测试推断。见 [ADR0042](adr/0042-paper-reading-document-and-notes.md)。
