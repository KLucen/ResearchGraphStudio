# 全局模型配置

打开左侧“设置与诊断”，在全局模型设置中管理配置；所有项目共用。新增配置后点“测试连接”，再分别选择 Extraction 和 Reasoning 模型。两个角色可以使用同一配置。正常设置页仅提供 OpenAI、兼容 API 和本地模型。Mock 仅留给显式自动化测试与历史兼容，不可作为全局生产模型。

## 配置与参数

- OpenAI 固定官方 `https://api.openai.com/v1`，填写账户实际可用的 Model ID 和 API Key。
- OpenAI-compatible 使用供应商的 API 根地址（通常含 `/v1`）；本地模型仅允许 loopback 地址，如 `http://127.0.0.1:8000/v1`。服务须支持 Chat Completions 文本接口。
- Temperature、Top P、Reasoning effort 留空时不发送该参数；按模型实际支持能力选择。不再提供手动“最大输出 Tokens”。连接或运行时从同一端点 `/models` 中匹配精确 Model ID，读取输出上限和上下文窗口；有可信输出上限时自动使用，OpenAI 为 `max_completion_tokens`、兼容/本地为 `max_tokens`，并预留输入上下文。未返回能力时省略限制参数、使用服务默认值，界面明确显示未知；不将模型别名或上下文长度猜作输出上限。可关闭不受支持的 JSON Object 请求模式，但服务端仍严格校验 JSON 和领域 Schema。
- 测试连接仅发送固定的非论文文本，检查调用可达及 JSON 回答。连接成功不代表科学抽取质量通过。

## 密钥与隐私

Windows 版本通过 Credential Manager Generic Credentials 保存密钥。数据库仅保存随机凭据引用；API 列表、模型记录和错误消息不返回密钥。React 不将密钥放入 localStorage 或查询缓存，提交后清空输入框。无安全后端的平台拒绝保存密钥。

编辑时留空保留密钥；更换服务类型或 Base URL 后须重新录入，防止旧密钥发送给新端点。排队任务冻结非敏感配置和凭据引用，旧凭据保留供已排队任务使用；删除配置会删除该配置各版本的 OS 凭据并清除角色选择。运行数据库备份不包含凭据，换机器/Windows 用户需重新录入。密钥丢失时失败，不回退明文。

抽取/推理会另行要求同意发送所选论文或主张的证据文本。仅使用预定义文本接口，无 SQL、Shell 或文件工具。私人笔记不参与。远端必须 HTTPS，不接受 URL 内凭据/查询参数，不跟随重定向；当前请求直接连接，不继承系统代理。

## 2026-11-02 输出截断与恢复

后续抽取可靠性修正：新 P02 3.2 使用 8000 字符/64 证据目标，旧任务继续原计划。新增 timeout_phase 诊断，在明确响应等待超时时将失败根批拆一次，缩小后仍超时就停止自动重发；连接阶段、限流与服务错误仍有界重试。原有默认 90 秒及设置 5–180 秒范围不变。已知 null 占位字段可确定性处理，不重新收费调用模型。见[本轮验收](extraction-reliability-verification-20261102.md)。

排队任务冻结模型和参数；设置页改为 65536 不会回写此前按 8192 排队的任务。当前 Provider 不再发送历史手工限制，但保留原快照用于审计。输入按内部有界预算合并，遇到输出/上下文上限只拆失败叶批，保留已提交知识与模型原始结果；最多三层，不能无限重试。任务历史用“继续未完成批次”，批次总数可能因拆分增加。

本机实际供应商的 `/models` 未返回上下文或输出上限，因此本轮使用供应商默认。真实库副本上 4 次调用均通过 Schema、证据和 Store 校验；剩余整篇未跑完，不承诺服务默认等于模型最大值。详见 [本轮验收](refinement-verification-20261102.md)。
