## 产品目标

ResearchGraph Studio 是辅助阅读、理解和整理科研论文的通用桌面产品。统一称“知识图谱”。不要求用户预设学科、研究方向、领域词表或问题才能使用。相关性首先衡量内容对理解当前论文的研究问题、贡献、论证和限制是否必要；专业维度从材料中提取，不写死某学科的实验参数。

## 必须保持的四项原则

1. 原文段落、表格原始材料、证据定位和模型原始输出保留；解析失败也保留原始材料及失败原因。完整保留不等于承诺所有表格都已结构化。
2. 抽取到的 Claim、Method、Finding、Condition 等首先进入同一 Knowledge Store 的候选层。全量原文保留不要求逐句实体化。
3. 经过相关性、证据完整性和重复检查的内容才能被自动选择到默认图谱。
4. 未选内容继续保留、可由后续 Query 检索；用户可用展示偏好调整核心内容。收起、隐藏、未入主图均不删除知识。

## 产品流程

选择 Zotero 论文/PDF → 一键生成知识图谱 → 自动解析、候选抽取、论文级整合、核心选择、发布 → 逐层浏览与原文回查。

完整目标延伸为：图谱组织结论与支撑→Query按问题沿合法路径扩展并补原文/候选/有效Wiki/授权个人资料→明确保存为衍生综合→明确整理Wiki→授权导出Markdown，Lint横向检查来源、支撑、依赖和文件状态。知识图谱提供组织与推理上下文，画布只是其交互视图。完整图见[项目介绍](../README.md#从论文到阅读知识)，实施顺序见[开发计划](06_development_migration_plan.md)。当前仅自动建图与阅读交互已接入，P4/P5尚待实现。

**新流程没有人工审核、待审队列、接受/驳回或审核门槛。** 确定性校验失败自动隔离；上下文不足自动保留为仅检索候选并说明原因；可恢复的技术失败提供继续入口。用户改变展示密度/核心偏好是视图配置，不授予科学真实性。旧审核记录只作历史兼容，不能删除，也不能要求新任务继承审核步骤。

## 图谱组织

默认 Paper → 核心 Claim → 有据非 Claim 支撑，包括 Method、Experiment、Condition、Finding、Metric，以及有合法关联的论证、限制、概念等。支撑分支可显式收起，证据在详情按需查看。来源归属保存为元数据，不为所有节点补 Paper 连线；没有支撑时不造节点。KnowledgeUnit 引用已有知识与关系，允许共享支撑节点，不复制主张。层级导航线和科学关系线明确区分。

首次语义整合/排序失败时，只可展示来源与归属通过保守门槛的 provisional 结论及已有支撑，明确 ranking_status=pending、build_state=partial；它不代表核心贡献排序已完成。已有图保留，来源或快照变化时停止，不发布降级视图，也不靠再次收费修复。

实验、方法、理论、综述与混合论文使用共同底座，一级 Claim 分别表达实验发现、方法贡献、理论结论、综述综合判断或重要限制。不会为理论或综述强造实验。

## 自动化与可信边界

- 证据锚定证明来源可定位，不证明科学结论真实；作者主张、转述观点、AI 关系与用户笔记分别归属。
- 所有知识变更经 KnowledgeStore，LLM 仅输出白名单引用与严格 DTO，不生成正式主键、页码、审核状态，不操作 SQL/文件。
- 原文与历史模型输出不可因重跑覆盖；任务/语义/选择/布局版本分开，已提交批次复用，失败费用未知不能写成零。
- Zotero 与私人笔记只读；不长期重复保存 Zotero PDF。保留索引及原模型输出不属于临时文件清理范围。
- Query 默认只读；保存回答与向授权目录导出 Wiki 是明确的数据写入动作，不是人工科学审核步骤。

后续Query/Wiki/Obsidian边界见[ADR0018](adr/0018-query-wiki-and-obsidian-lifecycle.md)：Query应兼读Wiki内容及状态，P4先有最小文档登记/只读适配；Wiki是有据阅读文档，不是现有知识图谱。保存问答新增衍生知识，整理Wiki与导出文件另行明确；私人笔记只读，Lint区分内容依赖与文件同步问题。本轮只补充规划，不宣称这些能力已实现。
