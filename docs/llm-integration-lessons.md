# 大模型调用故障与修复经验

更新：2026-11-21（Asia/Shanghai）。本文件提炼已记录的故障和当前修复方法；实际测试、费用和交付结果仍以对应DEV条目及验证报告为准。不能把合成回归当作真实科学质量，也不能承诺模型永远不产生无效输出。

## 反复出错的根源与最终处理

| 问题 | 真正原因 | 已采用的处理方法 | 保留的边界 |
| --- | --- | --- | --- |
| JSON合法但关联编号不存在（DEV-0027） | 结构合法不代表引用属于输入 | 输入短编号白名单、上下文/引用终验；仅明确范围内修复 | 不把随机新ID或猜测的归属当作有效来源 |
| Claim多出`kind_note_unused=null`（DEV-0038） | 运行契约和模型照抄的字段不一致 | 仅兼容已观察到的精确null形态并记录规范化审计 | 非null、其他额外字段和冲突仍拒绝，raw保持 |
| 排序数组重复抄ID、漏槽和extra（DEV-0047） | 把结构搬运与排序交给模型 | 程序生成required键槽、绑定ID，模型只填内容/priority，程序排序；Prompt和Schema同源 | 未知槽和冲突不合并，不靠更换模型或继续收费掩盖协议问题 |
| 点击继续反复看到旧失败（DEV-0048） | 幂等接口可能返回已完成/运行中的后继，界面没定位返回Job | 展示实际返回任务并读取真实状态，复用成功检查点 | 原失败不改成成功，已发请求不自动再发 |
| 精读CLAIM/THESIS和引文错误（DEV-0120、ADR0057） | 类型语义表达不清，字段校验和来源校验混为一谈 | 新Prompt清楚定义类型；精确类型映射须显式本机恢复，引文错误隔离并标partial | 只修确定性格式，不补写科学原意，保留raw和原失败 |
| `KNOWLEDGE_INPUT_BUDGET_EXCEEDED`（DEV-0125、ADR0061） | 默认48K低于完整请求；部分路径把UTF-8字节当Token | 输入/输出/请求数的nullable预算贯通全链路；估算与传输大小分开；冻结/当前策略取严 | “无上限”不取消端点容量、累计预算、授权、来源终验；估算不是计费用量 |
| 所有失败都显示Schema错误（DEV-0126、ADR0062） | ProviderError继承ValueError，分类顺序错误；失败metadata丢失 | 先区分服务/网络/超时/截断，再处理JSON/DTO/来源；保存实际私有metadata，任务条目显示安全原因 | 公共诊断不回显原文、密钥、供应商body或未知字段值；旧缺失细因不反推 |
| 180秒后即使有推理流也停止（DEV-0127、ADR0063） | 总时限与无活动时限混用，网络字节与生成未分记 | 新文字快照使用activity；正文/公开reasoning增量续期；连接单独计时；心跳不算生成 | 隐藏思考不可观测；旧冻结快照保持；文档限时独立；取消关socket而不重发 |
| 知识图关系校验失败（2026-11-21本轮） | Schema给了关系枚举，却未表达端点类型/方向规则；模型自然生成的关系不符合隐藏规则 | 新v2合同从实际规则表生成Prompt/Schema描述/输入规则；逐条显示关系错误；完整合法节点与合法边可显式本机隔离恢复为partial | 不把`USES`猜改成`ANALYZES`，不静默删边/放宽科学关系；恢复仍完整验字段、引文和当前来源，原失败/raw保持 |

## 后续修改模型功能的固定流程

1. **先读取保留的失败证据。** 明确是否真正发送、是否取得完整响应、哪一级失败；只输出安全字段路径/类型/计时等元数据。不因一个通用错误码就断言“模型格式不对”。
2. **逐级定位。** 配置/传输 → JSON语法 → 字段DTO → 对象之间的约束 → 引文/来源 → 发布与依赖。修复上一层后仍须执行所有后续终验。
3. **生成合同必须包含实际约束。** 不只列字段和枚举，还要传递关系端点、方向、唯一性、完整槽位、未知值和引用归属规则。说明和Schema由实际校验规则生成，并以匿名合成响应检验一致性。无法在供应商Schema中表达的约束仍由本机校验，不宣称原生strict能覆盖。
4. **把确定性工作交给程序。** 程序生成正式ID/槽位/版本/来源身份和排序；模型填写语义。对用户材料中的指令按不可信数据处理，不让模型执行SQL/Shell或写文件。
5. **失败样例回归采用匿名形状。** 使用相同错误类型、节点/关系组合和边界，不把私人论文或raw复制到仓库；同时保留拒绝未知字段、错引文、来源变化、取消、并发和重启用例。
6. **恢复必须说清楚损失。** 精确无损转换可按既定规则审计；有来源的部分内容只能明确标为partial并列出隔离项；需猜测语义或来源已变时停止。预览、确认和发布指纹绑定同一原响应/来源，不能“修成能过Schema”就视为正确。
7. **版本与消费账本不重写。** 新Prompt/请求合同单独版本化；旧任务用原快照，旧成功检查点不重发。只读诊断不发布、不改旧状态。新真实请求需明确授权和预算，不能为验证兼容性偷偷探测或自动降级重发。
8. **完成整个产品闭环。** 同步FastAPI、TypeScript、Rust代理白名单、界面状态和幂等；验证实际HTTP、打包引擎、安装版和重启。只通过一个模型函数测试不能代表桌面端可用。

## 不作为修复的方法

不使用`extra=ignore`、任意删未知字段、放大字段长度或关系白名单、补造引文、改写raw、把所有失败归Schema、增加隐式重试或更换收费模型来隐藏问题。JSON可解析、引文精确匹配和科学结论成立是不同层次，必须分别表述验证结果。

## 新版卡片合同的预防措施（ADR0065）

新版不再让模型同时构造图谱、位置与重复来源引用。严格DTO直接生成输出Schema；模型只填写短编号、正文和精确引文，程序绑定正式身份、章节、页码与偏移。总览引用有据卡片；优点/不足分析与作者自述局限分开。保存后从wire_draft和当前完整来源重建比较全部字段，避免只验证JSON结构却信任被改写的正文/位置。

复用概览表时，所有读路径都须区分版本，尤其是知识库旧收藏、精读关联和布局接口；不能因表相同就把新版卡片当成旧图谱。模型后处理不仅比较发送正文，还冻结完整来源指纹，防止正文未变但定位或表格结构变化漏检。测试分别覆盖发送前/后变化、取消、失败发布回滚后的raw/用量、已发送槽位与重启零重发。

应用退出的协程取消也要纳入持久化路径：`asyncio.CancelledError`不属于`Exception`，须专门捕获，保留Provider已收到的partial/usage并标中断后重新抛出，不能依靠普通except保存。发送前先执行同一确定性请求预检；若端点metadata发现更低容量后、本机再次明确在生成POST前拒绝，保留发送意图槽但明确标`generation_request_sent=false`，用量聚合只排除此确定未发记录，未知网络状态继续保守记账。
