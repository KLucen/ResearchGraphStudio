# 创新验证与实验计划

版本：v0.3；依据：[QA.md](../QA.md) 第 620–708 行及[补充材料 S3/S4](../docs/design/source-register.md)。状态：**实验协议规划，尚未运行实验或取得指标。** 与[开发计划 v0.4](../docs/development-plan-v0.4.md)同步，E1/E2/E3 保持原编号，新增 E4/E5/E6。

## 1. 主实验与补充实验

| 实验 | 假设 | 对照与主指标 |
| --- | --- | --- |
| E1 条件约束的证据推理 | 显式比较实验条件能减少错误支持/冲突 | A：LLM 直接判断主张对；B：LLM + 原文证据；本方法：LLM + 同源证据 + 结构化条件比较。五类 Macro-F1、各类 Precision/Recall、错误冲突率、证据定位准确率 |
| E2 增量知识演化 | 保持必要关系召回时，局部重算比全量重算成本更低 | 相同工作区/批次下的全量关系重算 vs 候选影响集合 + 局部重算；耗时、Token/费用、影响关系召回、结果差异 |
| E3 人机协同审核 | 证据图谱与审核界面改善跨论文比较任务表现 | 普通 AI 总结/问答界面 vs 证据图谱/审核界面；正确率、时间、证据核查次数、认知负担与体验 |
| E4 结构化抽取 | Schema 与证据锚定减少抽取/归属错误 | 自由格式抽取 vs 同模型 Schema 约束抽取；主张 Precision/Recall/F1、误归属、条件/数值遗漏、证据匹配 |
| E5 实体融合 | 上下文和类型核验减少错误合并 | 字符串/别名 vs 语义相似 vs 加上下文校验；合并 Precision、错误合并率、候选召回 |
| E6 问答与新鲜度 | 持续更新的 Wiki/证据图减少过期和无依据答案 | 向量 RAG vs 定义明确的静态图检索 vs 演化 Wiki/证据图；正确率、引用支持、不支持主张率、过期结论率、成本 |

E1/E2/E3 保留原设计的关系、演化、人机主实验。新增 E4/E5 用于流水线诊断与消融，E6 对应新增 Query/Wiki 研究问题；检索 Recall@k 不是 E1 的替代实验，不能将不同任务的准确率混成一个总分。

## 2. 数据与标注

- v0.1 先选择至少 5 篇相互关联、可使用的英文计算机科学论文做端到端样本，搭配自造 PDF 验证页码/坐标边界。
- 研究版按 QA 准备 20–30 篇论文、约 100–200 组有方向的候选主张对。标注主张、双方证据位置、条件、五类标签、歧义和判定理由；包含条件不同、证据不足与同词异义的负例。
- 至少两名标注者独立标注部分重叠样本，报告一致性并仲裁分歧；不能将同一模型生成标签再让其自评作为唯一金标准。
- 按论文组或主题划分开发集/测试集，避免同篇论文的重叠证据跨集合。先固定测试集和标签，再调整提示词、阈值和检索参数。
- QA 提到 SciFact 可辅助测试科学主张证据验证，但它不等同于本项目的跨论文实验条件五分类任务；使用前核对版本、许可和标签映射，不直接合并分数。
- 100–200 对是先导规模，不是统计充分性的保证；正式实验规模由先导方差和可用标注资源决定。保持每类样本数可见，测试集中缺少类别时必须说明指标限制。

## 3. E1：分类与证据约束

A/B/本方法固定同一模型版本、主张对和划分；B 与本方法使用同一组可访问证据。本方法的结构化条件从同一文献抽取，不额外加入测试标签或人工答案。固定最大上下文/输出预算与推理参数，记录实际 Token 用量；不通过给本方法更多文献制造不公平优势。

先在固定标注主张对上评关系分类，隔离召回与抽取误差；再跑完整链路，分别报告证据抽取、候选召回和分类结果。缺失或非法输出记为错误，不悄悄从分母删除。INSUFFICIENT 单独报告 Precision/Recall 和有效判定覆盖率，防止全部输出证据不足造成虚高印象。

指标定义：五类 Macro-F1 为 SUPPORTS、CONTRADICTS、QUALIFIES、EXTENDS、INSUFFICIENT 的类别 F1 平均；同时给出混淆矩阵。错误冲突率按非冲突标注对中被判为 CONTRADICTS 的比例计算，并报告冲突预测的误报比例以避免口径混淆。

证据定位准确率：被抽查的预测证据中，可在正确论文/页/文本片段或标注区域定位的比例。另报证据召回和有效输出数，避免只输出少量简单证据抬高准确率。定位正确不等于该证据在语义上支持主张，二者分开审核。

## 4. E2：全量与增量对照

固定加入文献的顺序和批次，在工作区达到 10、20、30 篇等规模时比较两条路线。全量路线对当前全部候选重新推理；增量路线只处理筛选出的影响集合，两者使用同一抽取产物、模型、条件推理器和候选规则。

新增“只追加新知识、不复查旧知识”作为朴素基线，检查其速度收益是否来自漏更新。Wiki/笔记进入研究版后，影响集合包含旧关系与页面段落；分别报告关系召回和页面更新召回，不用页面数量掩盖关键关系遗漏。

耗时边界统一：本次新文献解析/索引、候选生成、需要的模型调用、状态写入。分别报各子阶段和总时间，区分冷/热缓存；不将历史解析缓存只提供给一方。重复运行并记录均值/中位数、离散程度及模型非确定性。

影响关系召回分别对人工标注变化集合和全量基线变化集合报告；全量输出不是绝对真值，出现差异须人工分析。未经用户确认的增量输出只形成提议，不能让增量策略跳过审核以降低耗时。

同时验证回放与幂等：同一事件序列产生一致物化状态、重复任务不生成重复边、旧的已接受关系不被覆盖。回放正确是工程要求，不直接证明增量算法召回充分。

## 5. E3：用户任务研究

使用难度相近的论文比较任务，控制参与者经验与练习量；以随机分配/顺序平衡减少学习效应，避免同一参与者先看一界面答案再做完全相同任务。两个条件尽可能共享文献、模型和底层输出，以解释界面与审核机制的作用。

任务答案由独立标注标准判定。记录完成时间、正确率、证据核查次数，以及固定问卷的认知负担和体验。先做小型可用性试验再决定正式样本量；若缺乏足够参与者，应如实报告可用性观察，不能称为已完成受控用户实验。

补充每 100 条候选的审核/修订用时、修改比例与审核一致性；按候选难度和正确/错误分布分层，避免通过只输出简单候选降低表观成本。时间归一化时同时报告原始候选数，少量样本外推需注明限制。

## 6. 原文目标与验收口径

| 指标 | QA 目标 | 使用限制 |
| --- | --- | --- |
| 证据定位准确率 | ≥90% | 在冻结样本上按上述定位口径统计，同时给出覆盖/召回 |
| 关系分类 Macro-F1 | ≥0.75 | 自建五类标注集；同时报告逐类和区间 |
| 增量更新总耗时 / 全量重算总耗时 | ≤60% | 在相同规模/边界下比较，必须同时报告影响关系召回 |
| 已接受实质关系的溯源完整率 | 100% | 所有 accepted 的实质关系都具有效来源主张与证据；无对象时记 N/A，不记100% |

全部是目标值，不是测量结果。QA 未给影响关系召回最低阈值；在先导实验后、冻结正式评测之前确定，并记录理由，不能仅凭速度达标认定增量方法通过。报告置信区间、失败案例和相对基线差异，不以达到阈值代替创新性论证。

## 7. 排期、复现和产物

Phase 1 制定样本清单、标注规范与相关工作检索计划；Phase 2 建 E4 并准备 E1；Phase 3 建 E1/E5、E3 先导；Phase 4 开展 E2 关系/页面更新先导；Phase 5 建 E6；Phase 6 冻结并运行正式批量评测、用户研究和报告。正式测试集应在调参前划定，不能把 Phase 6 才开始准备样本当作合理流程。

每次运行保存 run_id、Git revision、输入/数据划分哈希、解析器/模型标识、Provider、提示词版本、参数、原始预测、错误、重试、耗时、Token/可得成本和指标。仅在供应商支持时记录精确模型快照；云端运行通常只能保证配置可追溯，不自动保证逐字复现。

规划目录为 datasets/、baselines/、evaluation/；数据与脚本将在对应任务建立。私人论文和运行输出置于被忽略的 experiments/runs/ 或外部目录；只提交可分发样本、匿名汇总、配置及评估脚本。当前没有实验结果文件。

## 8. E4/E5：抽取与合并的诊断协议

E4 固定相同论文段落、模型和预算。人工标注最小可独立核验主张，保留归属、否定、条件和数值单位；按预先冻结的语义匹配规则匹配预测与金标准，重复预测不能重复计 TP。Precision=正确匹配预测/全部预测，Recall=被命中的金标准主张/全部金标准主张；非法输出计失败。定位正确与语义支持正确分别报告。

E5 使用等价/不等价概念对，并包含上位/下位概念、缩写歧义、相同名不同语境。合并 Precision=正确合并/全部合并；错误合并率=错误合并/全部合并，另报不等价对误并比例，避免分母混淆。没有合并时精确率记 N/A，同时报告覆盖率；候选召回与最终合并判定分开。RELATED_TO 不算等价合并或第六种主张关系。

E4/E5 需要新增人工标签，不能把现有 100–200 个关系标签直接当抽取和融合金标准。至少部分样本双人标注，报告争议、仲裁与适用范围。

## 9. E6：问答与知识新鲜度

所有方法使用相同截至时间的原始文献、同一问题集和模型预算。动态方法可以维护派生知识，必须报告建库/更新成本；静态图检索的具体算法、更新政策与缓存必须写清，不能把自制简化图检索称为完整 Microsoft GraphRAG 实现。

设置新增文献前后的时间截面，问题涵盖单文事实、跨论文条件比较、已改变结论和证据不足。冻结题目与人工答案；开发提示词/Wiki 时不接触测试答案。增加静态 Wiki 或关闭依赖更新的消融，以区分综合视图与更新机制的收益。

答案按主张级标注：正确率按预定任务评分；引用支持率=被引用来源确实支持的答案主张/带引用主张；另报有需要但未引用的主张覆盖。无依据主张率=无有效来源支撑的实质主张/全部实质主张。过期结论率=仍沿用已被新证据要求修订内容的回答/应受更新影响的回答。空分母记 N/A，不记完美成绩。拒答/证据不足和有效作答覆盖率同时报告。

知识新鲜度不等于把最新文献一律视为正确；标注需结合证据质量、条件与更新理由。云模型输出不确定性通过重复运行和误差区间说明，不将裁判模型单独打分作为唯一真值。
